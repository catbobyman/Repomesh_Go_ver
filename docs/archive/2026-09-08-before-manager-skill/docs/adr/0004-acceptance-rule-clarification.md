# ADR-0004：缺失业务验收规则的解释由人确认

验证过程中可能发现需求尚未明确某条业务规则，导致同一结果存在不同的通过或失败解释。用户确认：Agent 可以提出解释和测试建议，但须经人确认，才能用该解释判定相关检查通过或失败。这样保留业务含义的人工决定权，接受相关检查需要等待澄清的成本。

## 已确认的边界

- Agent 可以指出缺失规则、提出可能的业务解释和相应测试建议。
- 未经人确认，Agent 不得将自己提出的业务解释作为相关检查通过或失败的依据。
- 本规则处理的是业务验收条件尚未定义完整的情况。[ADR-0003](0003-plan-change-authorization-and-activation.md) 中“放宽已确认验收条件由人决定”的边界继续适用。
- 人确认业务解释，不自动表示代码通过验证，也不自动表示计划变更已经生效；如涉及计划变更，继续按 ADR-0003 处理。

## 场景

frontend F1 + backend B1 的“支付状态筛选”需求未说明“已支付后退款的订单是否包含在已支付结果中”。Agent 可以提出包含或排除的解释及测试建议；在得到人确认前，不能依据自行选择的解释判定相关检查通过或失败。本例不决定退款订单应如何筛选。

## 仍待讨论

本次只确认上述业务解释的决定权，尚未确认完整的验证节点输入、证据要求、结果分类和执行职责。具体由谁确认、怎样记录和关联确认依据，以及等待澄清期间其他检查如何继续，仍需逐项讨论；不据此承诺运行中按单个图分支暂停或派工。

跨仓验证人员配置、联调环境、Graph/Loop、人工审查与 PR 时机、合并及回退继续按既定顺序讨论。领域术语仍见 [CONTEXT.md](../../CONTEXT.md)，不将本规则写入术语表。

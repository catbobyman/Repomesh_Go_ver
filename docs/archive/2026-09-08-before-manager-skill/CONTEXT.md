# RepoMesh 领域语言

RepoMesh 围绕多仓库项目组织长期团队，以独立 issue 推进可验收的交付。本文仅定义领域术语，不规定部署方式或实现技术。

## Language

**多仓库项目（Project）**：
由一组相关代码仓库、业务目标和协作规则组成的长期工作范围，归一个 Manager 负责。不同项目具有各自的成员授权和协作归属，每个项目可以持续接收多个 issue。
_Avoid_: 用“项目”同时指代一条 issue、一次执行或一条聊天。

**项目草稿（Project Draft）**：
已经取得稳定项目身份、但尚未完成仓库授权或其他必要配置的多仓库项目。草稿可保存和继续编辑，但还不能进入正常 issue 执行流程。
_Avoid_: 将“尚未完成配置”和“配置已完成但运行实例尚未启动”混为同一状态。

**需求事项（Issue）**：
项目中的一次独立目标，具有自己的范围、讨论、计划和验收条件，可以涉及一个或多个仓库。来源仓库不自动决定它的影响范围。
_Avoid_: 把 issue 等同于一个 Worker 任务或一个新 Manager。

**项目仓库范围（Project Repository Scope）**：
一个多仓库项目明确接入的仓库集合，限定该项目可开展工作的仓库边界。具体工作还受发起人的有效授权以及所属 Team、Task 的范围约束。
_Avoid_: 将接入仓库等同于授予全部操作权限，或认为项目成员自动获得所有接入仓库的访问权。

**项目负责人（Manager）**：
对一个多仓库项目负责的长期协调角色，承担范围不明或跨仓 issue 的协调，并掌握项目整体进展。
_Avoid_: 将 Manager 身份与某一 issue 的会话混为一谈。

**仓库团队（Team）**：
在一个项目内长期负责一个代码仓库的组织，由一名 Leader 和若干 Worker 组成，可连续参与该项目的不同 issue。
_Avoid_: 每条 issue 重新建立的临时组织、所有成员共用的一份工作目录。

**跨仓验证小组（Cross-repository Verification Group）**：
项目内专门承担跨仓验证工作的成员集合，其工作围绕分配的验证节点及对应验收范围组织。
_Avoid_: 将验证小组等同于负责某个业务仓库的 Team。

**验证负责人（Verification Coordinator）**：
跨仓验证小组的固定协调角色，承担组内任务安排、证据完整性核对和结果汇总，并向 Manager 回报。
_Avoid_: 将验证负责人等同于跨仓 issue 的主负责人或业务仓库的 Leader。

**仓库负责人（Leader）**：
一支仓库团队的协调角色，负责本仓工作拆分、派工、结果初审和阻塞升级。
_Avoid_: 普通执行成员、另一个项目 Manager。

**执行成员（Worker）**：
承担具体、有边界、可检查工作的执行角色。成员身份可以复用，但不同工作的过程和产物需要区分。
_Avoid_: 将成员身份等同于一条 issue 或某次执行尝试。

**事项负责人（Issue Owner）**：
某条 issue 当前唯一的主协调责任人，可以是 Manager 或具备单仓处理条件的 Leader。参与该 issue 的其他 Leader 仍对各自仓库工作负责。
_Avoid_: 多个角色同时声称拥有同一 issue 的最终协调权。

**事项会话（Issue Session）**：
某个角色围绕一条 issue 保持的独立讨论上下文。即使多个角色参与同一协作讨论，各角色仍拥有各自的事项会话；跨仓 issue 可以包含 Manager 主会话，以及各仓 Leader 和参与 Worker 的仓库子会话。
_Avoid_: 将会话与长期 Agent 身份或整个团队的公共讨论混为一谈，或把共同可见的消息误认为所有角色共享同一份模型上下文。

**事项计划版本（Plan Version）**：
某条 issue 在特定阶段的一份明确工作安排，描述工作内容、依赖、范围以及预算和循环约束。版本身份用于区分提出、获准和实际生效的安排。
_Avoid_: 将已批准版本等同于当前有效版本，或用修改后的内容冒充原版本。

**计划变更（Plan Change）**：
针对既有事项计划版本提出的调整，包含目标版本、具体差异和变更原因，具有自己的许可判断与应用结果。
_Avoid_: 将提出变更、获得许可和变更生效视为同一个事件。

**自动化档位（Automation Mode）**：
规定计划变更由策略自动判断还是由人审批的控制选择。它描述编排决定的许可方式，不代表额外的仓库访问或操作权限。
_Avoid_: Git 权限等级、无条件跳过全部检查。

**计划生效（Plan Activation）**：
某个事项计划版本已经应用并成为后续执行依据的事实，与该版本是否已经获得许可分别表达。
_Avoid_: 批准即生效、发出应用请求即生效。

**工作任务（Task）**：
从 issue 的计划中拆出的具体工作单元，具有明确负责人、输入、输出、依赖和验收条件。
_Avoid_: 将任务提交成功等同于整个 issue 已经完成。

**执行尝试（Attempt）**：
对一项任务的一次具体执行记录，包含本次过程、结果及终止原因。重派或重新执行保留此前尝试的历史。
_Avoid_: 用新结果覆盖旧尝试，或将恢复与重新执行不加区分。

**候选结果（Candidate）**：
执行成员提交、等待检查和接受的产物，不代表该任务或 issue 已通过全部验收。
_Avoid_: 已提交即已交付。

**交付组合（Delivery Combination）**：
为验证同一 issue 而选定的一组仓库候选版本。组合内任一版本变化，都需要重新判断原验证证据是否仍适用。
_Avoid_: 各仓单独成功即整体成功。

**暂停（Pause）**：
暂缓某条 issue 后续工作的控制决定，不自动表示在途工作已经停止，也不意味着已交付变更被撤回。
_Avoid_: 将暂停、停止执行、取消和回滚当作同一操作。

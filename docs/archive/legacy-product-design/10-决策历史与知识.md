# 10 · 决策历史与知识

## 决策历史

每个需求形成一条可追溯的历史链，回答“谁在什么时间作了什么判断、为什么、依据是什么、后来如何改变”。

| 编号 | 功能 | 规则与呈现 |
| --- | --- | --- |
| HIS-01 | 自然语言检索 | 用户描述要找的历史问题，查看相似结果、相似程度和来源需求；检索能力未配置时明确提示 |
| HIS-02 | 需求定位 | 根据标题关键词、短编号或完整编号查找；单一命中直达，多条命中先展示候选 |
| HIS-03 | 五步决策链 | 顺序展示圈定范围、人工确认、安排执行顺序、拆成任务、提交交付；顶部可点击跳转对应步骤 |
| HIS-04 | 当前版本与旧版本 | 前三步显示当前生效版本，旧版收进版本时间线并可展开；任务和交付实例逐条列出，不错误合并 |
| HIS-05 | 证据溯源 | 展开操作人、业务时间、记录时间、原决定、关联任务、交付组与证据，支持回到上下文 |
| HIS-06 | 缺口与未到达 | 中间步骤缺失显示“记录缺口”；流程尚未走到显示“未到达”；不自动补写缺失理由 |
| HIS-07 | 相似历史参考 | 从当前需求查看相似旧需求与决定，明确参考依据是内容相似还是相同仓库；复用前重新确认适用性 |

HIS-01 至 HIS-07 为保留。历史只能在用户获准的工作区与项目范围内查询；检索功能不能绕过权限。

## 链头与五步内容

| 部分 | 必须显示的内容 |
| --- | --- |
| 链头 | 原始需求、当前结果、需求与计划标识、最新有效版本 |
| 圈定范围 | 必改、待定、不做清单，以及选取理由 |
| 人工确认 | 确认人、理由、附加条件、调整内容及时间 |
| 执行顺序 | 批次、依赖、提供方与使用方关系、未解决事项 |
| 拆成任务 | 每项任务的名称、归属、指派与结果 |
| 提交交付 | 各仓评审请求、待合入或已完成状态及可访问链接 |

“有记录”表示这一阶段存在可查事实，不等同于业务成功。要求修改、拒绝和返工也属于有价值的历史记录。

## 上下文与知识功能

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| CTX-01 | 分层工作资料 | 管理组织职责、仓库背景、项目共享约定、任务与尝试资料，说明来源和适用范围 |
| CTX-02 | 版本与使用记录 | 每次工作固定当时使用的资料版本，之后资料更新不改写已发生的使用事实 |
| CTX-03 | 最小资料分发 | 根据角色、项目成员关系、任务范围和本次授权确定可读材料；任何明确拒绝优先 |
| CTX-04 | 资料补充 | 可顺序追加解释性材料；若改变目标、判据、范围或权限，必须进入正式变更流程 |
| CTX-05 | 独立动作权限 | 分别控制发现、阅读、提供给成员、发布、批准和导出资料，阅读权不推导其他权力 |
| CTX-06 | 访问审计 | 记录允许、拒绝、资料缺失和内容不一致，支持查明某次工作实际获得哪些信息 |
| CTX-07 | 结论转为共享知识 | 问答与发现经确认后形成有版本、有归属的正式资料，原房间聊天保留来源但不自动变为通用规则 |

CTX-01 至 CTX-06 为保留能力，其完整管理界面为补齐；CTX-07 为补齐的知识整理体验。

## 可见范围

资料区分组织可见、项目共享、团队私有、任务私有、单次工作私有与受保护秘密。某角色的最大可见范围只是上限，实际授权仍以本次任务所需为准。秘密内容不进入普通任务材料、历史检索或导出证据。

## 验收

1. 用需求关键词或编号能定位正确历史，多结果时不擅自选择。
2. 同一确认有多个版本时，当前版本和被替代版本明确可辨。
3. 人工确认之后直接出现任务而无顺序记录时，显示缺口而非推造计划。
4. 未提交交付的需求显示未到达，不能生成假外部链接。
5. 相似历史不会自动授予权限或替代当前范围确认。
6. 追溯一次尝试时能查到当时资料版本；资料更新不会修改过去记录。

## 产品级验收场景

| 场景 | 前提与操作 | 可观察通过条件 |
| --- | --- | --- |
| A01 首次使用 | 全新工作区，初始化管理员并完成向导 | 能进入工作台，失败步骤可恢复，敏感资料不外显 |
| A02 权限隔离 | 两工作区，两种监督范围 | 列表、计数、历史及操作均不越权 |
| A03 文档需求 | 分别导入有效、空白、超限和不支持文档 | 正确解析或具体报错，来源清楚，失败保留草稿 |
| A04 澄清 | 提交缺少约束的需求，补答或忽略 | 补答进入新分析；忽略留痕，不能无声跳过 |
| A05 多仓发现 | 需求同时涉及服务、界面和共享能力 | 逐仓给出依据、依赖、范围，缺权限仍保留阻塞对象 |
| A06 范围调整 | 将待定改必改并重生成计划 | 计划与确认范围一致，旧确认和修改意见可追溯 |
| A07 开工检查 | 让一个必需成员未就绪 | 开工拒绝且指出对象；就绪后重复确认只开一轮 |
| A08 两种执行方式 | 分别选择托管和本地方式 | 各自执行条件清楚，治理与验证要求一致 |
| A09 并行与依赖 | 两独立仓和一个下游仓 | 独立任务可并行，下游等待正确原因，同成员不重复执行 |
| A10 结果复验 | 成员自测成功，独立复验失败 | 不显示任务已合格交付，显示失败证据及返工路径 |
| A11 人工检查点 | 分别启用六类检查点 | 每类有实际触发、待办和恢复推进的完整路径 |
| A12 并发审批 | 两人同时处理同一有效待办 | 只接受一次，另一人看到已接受的真实结果 |
| A13 证据更新 | 批准后候选发生变化 | 旧批准失效，新版本需要新验证或审批 |
| A14 暂停取消 | 执行中暂停、恢复、取消 | 新任务按控制状态受限，取消不被误当成已交付成果撤回 |
| A15 增量计划 | 追加新仓及非法循环依赖 | 合法项留修订，非法项拒绝，旧工作不被改写 |
| A16 跨仓联调 | 冻结组合，执行通过、失败及环境阻塞场景 | 三种结果分开，保留最小证据和清理结果 |
| A17 数据交接 | 声明数据影响，遗漏检查后补齐 | 缺项返工；匹配候选且验证通过并清理完成才可放行 |
| A18 顺序交付 | 上游未完成而下游检查已绿 | 下游仍被阻断，全部实际完成后才整组成功 |
| A19 外部中断 | 交付已受理但回执延迟 | 保持等待确认，恢复后核对，不重复创建成果 |
| A20 冲突恢复 | 候选基准变化 | 形成冲突事项与修复，新候选重新验证审批 |
| A21 换人与迟到 | 原成员失联，换人后原成员回报成功 | 新尝试唯一有效，旧回报不影响正式结果 |
| A22 有界恢复 | 连续恢复失败直到预算耗尽 | 停止自动重试并形成一次人工升级 |
| A23 部分交付回滚 | 一仓已完成，一仓未合入 | 整组预览区分动作，逆序恢复，结果可逐项核验 |
| A24 历史缺口 | 有多个确认版本且缺一步记录 | 显示当前版、旧版、缺口与未到达，不编造 |
| A25 观测归因 | 有完整、缺失与近似关联记录 | 指标可对账，近似和未知明确显示 |
| A26 告警保护 | 两条告警同时触发，恢复其中一条 | 只解除自身保护，通知不重复，失败送达可见 |
| A27 技能发布 | 无证据晋级、试用失败、正常发布及回退 | 拒绝不合格晋级，回退停止新使用，历史可查 |
| A28 保留与恢复准备 | 清理普通日志且缺少真实恢复演练 | 不删业务证据，恢复准备不能假报通过 |
| A29 外部入口 | 启用扩展后发起指定版本执行 | 权限、范围、版本校验完整，重复指令不重复开工 |
| A30 离线原型 | 双击原型，遍历主要页面与模拟流程 | 页面可独立打开，演示身份和结果有明确标识 |

## 通用质量要求

- 可理解：每个阻塞说明对象、原因和下一步；未知状态不显示成功。
- 可恢复：浏览、网络中断和重复提交不丢失正式已接受的决定或重复执行。
- 可追溯：需求、计划、候选、验证、决定、交付和恢复的版本关系可查询。
- 可隔离：工作区、仓库、任务和尝试的权限范围明确；导出与历史检索同样受控。
- 可操作：关键操作能用键盘完成；窄屏可查看范围和确认按钮；错误不遮蔽全部页面。
- 可度量：时间、费用、成功率、等待时间和恢复次数有明确统计窗口与样本。

性能和可用性数值应在确认目标组织规模、同时执行量及部署条件后设定。本 PRD 不把未经验证的数字写成现状保证。

## 重写交接完成条件

逐项确认以上功能的保留、补齐或扩展范围；每项至少有入口、正常结果、异常结果和权限规则；明确首版选择及推迟理由。原型评审可确认页面与操作，真实执行、权限、外部交付和恢复能力仍必须按产品级场景验收。

# 01 · 产品总纲

## 产品定位

RepoMesh 是面向多仓库软件协作的智能交付工作台。用户提交一个需求，产品帮助用户找到相关仓库，明确需求边界，组织智能体团队分工执行，通过独立验证形成可审阅的交付结果，并在每个关键环节留下依据。遇到变化与失败时，用户可以追溯、干预、恢复或撤回交付。

产品的核心承诺是：每次交付都能回答“要解决什么、涉及哪里、谁在负责、为什么这样安排、验证了什么、当前卡在哪里、谁批准了、如何恢复”。

## 用户与职责

| 用户 | 主要目标 | 常用功能 |
| --- | --- | --- |
| 需求提出者 | 用业务语言提出目标并跟踪结果 | 新建需求、文档导入、澄清、查看进度和结果 |
| 项目负责人 | 管理范围、依赖、节奏与风险 | 范围确认、计划、监管策略、暂停、恢复、变更评审 |
| 仓库负责人 | 确认本仓责任及成果 | 仓库画像、团队、任务、验证、变更审阅 |
| 人工审核人 | 对授权范围内的关键事项作出判断 | 审核台、证据、批准、拒绝、要求修改 |
| 平台管理员 | 保证工作台及外部服务可用 | 首次配置、账户、仓库接入、运行方式、能力与运营管理 |
| 运营与审计人员 | 定位异常、解释成本和历史决策 | 观测、日志、告警、恢复记录、历史检索 |

一个人可兼任多个职责。账户身份、可见范围、审核权与修改权分别控制。

## 产品中的智能体角色

- **组织负责人（Manager）**：一个工作区的统筹者，接收需求，冻结范围与验证判据，向仓库队长派工，承接升级。
- **仓库队长**：一支仓库团队的负责人，负责本仓分工、问题汇总和结果初审。
- **执行成员（Worker）**：领取自己的任务，在获准范围内工作，提交结果与证据。
- **测试团队**：驻扎在测试资产仓的仓库团队，承担跨仓联调；保留同样的队长与成员结构。

智能体角色与人工审批身份分开呈现。

## 核心对象与关系

| 对象 | 用户理解 | 关系与约束 |
| --- | --- | --- |
| 工作区 | 一个组织的协作空间 | 管理需求、仓库、团队及权限 |
| 需求（Issue） | 一件希望被交付的事情 | 一个需求对应一个项目，可有多轮计划与交付 |
| 仓库 | 可参与交付的长期资产 | 可参与多个需求，有画像、权限和常设团队 |
| 范围 | 本次必须参与、待定和不参与的仓库 | 推荐范围与最终确认范围分开记录 |
| 规格 | 经过确认的目标、约束与验收依据 | 分项目、跨仓协作、本仓、任务四层；保留版本 |
| 计划 | 各仓的工作、先后关系和批次 | 只有确认后的有效版本可以开工 |
| 团队 | 锚定仓库的长期协作编制 | 一个队长、至少一个执行成员，可被多个需求引用 |
| 任务与尝试 | 分配给成员的工作，以及一次具体执行 | 重试产生新尝试，不抹去失败历史 |
| 验证快照 | 某一固定候选组合的验证依据 | 候选变化时，不能沿用旧结论 |
| 交付组 | 同一轮需要共同交付的跨仓成果集合 | 按依赖顺序推进，全部成功才算整组完成 |
| 审核单 | 等待人作出决定的事项 | 绑定明确范围、版本、证据和可处理人 |
| 房间 | 团队沟通与进度呈现空间 | 沟通内容不能自行改变正式任务和权限 |
| 恢复事项 | 一次异常及其处理过程 | 串联原因、决策、执行、复核与最终结果 |

## 端到端流程

1. 管理员完成账号与服务配置，登记工作区和仓库，检查团队可用性。
2. 用户填写需求或导入文档；产品识别信息缺口并发起澄清。
3. 产品推荐相关仓库，给出评分、证据、依赖和三档建议。
4. 用户或已授权角色确认范围与版本，生成规格、协作约定和执行计划。
5. 用户设定监管方式，检查实际参与团队与执行能力，确认开工。
6. 团队按依赖分批工作；用户查看任务、房间、尝试、阻塞和成本。
7. 候选成果依次接受队长初审、独立复验及所需联调；数据变更追加专门验证。
8. 产品汇总交付组、检查门禁、请求必要审批，按依赖顺序提交交付。
9. 交付完成后保留证据及历史；失败、变更和部分完成进入恢复或整组回滚流程。

## 全局业务规则

- 范围确认前不启动正式执行；运行条件不满足时明确列出阻塞。
- 任务完成、队长认可、验证通过、审核批准、交付完成是不同状态。
- 批准只对当时的范围与证据有效；重要内容变化必须重新评估。
- 重复点击、刷新和网络恢复不产生重复需求、任务、审核或交付。
- 仓库团队长期存在，需求结束不自动解散团队。
- 工作区隔离与任务授权同样约束查看、操作、历史检索和自动化能力。
- 无数据、未接入、检查失败、状态过期和业务失败分别展示。
- 暂停不代表取消，取消不代表撤回已经完成的交付。

## 范围与成熟度

本组 PRD 是重写的全功能基线，覆盖现有功能及材料中明确提出的补齐项、扩展项。各分册以“保留／补齐／扩展”标注，不能据此宣称现有产品已经完成所有验收。

核心交付范围到“可审阅候选、仓库合入及其恢复”为止。正式生产环境部署、流量切换和自动恢复属于扩展能力，另见第 12 册。

## 产品成效

关注需求到范围建议时长、范围直接接受率、漏选与误选率、开工到候选结果时长、首次验证通过率、人工等待时长、每轮消耗、交付成功率、恢复时长及重复操作数。指标应标明观察窗口、样本量与统计口径，不把目标值当成已达成成绩。

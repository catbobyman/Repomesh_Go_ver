# 09 · 观测、用量与告警

## 观测功能

| 编号 | 功能 | 操作与结果 |
| --- | --- | --- |
| OBS-01 | 观测总览 | 汇总轨迹、用量、日志、告警入口与当前活动异常；显示数据更新时间、来源覆盖和不可用项目 |
| OBS-02 | 会话轨迹 | 按会话查看智能体活动时间线，展开可获得的输入输出摘要、工具调用、技能使用、耗时、结果与关联任务 |
| OBS-03 | 跨会话事件检索 | 跨会话筛选事件和工具活动，定位失败点；支持分页、展开详情和回到原会话 |
| OBS-04 | 按需求追踪 | 按需求查看关联轨迹、任务、日志和用量；精确关联与时间邻近推测分别标注 |
| OBS-05 | 用量大盘 | 选择 7／30／90 天，查看调用量、输入输出消耗、估算费用、成功率、平均及高分位延迟 |
| OBS-06 | 消耗归因 | 按日、模型、发现步骤、需求聚合，并查看最近异常；显示币种、窗口、样本量和缺失归属 |
| OBS-07 | 日志时间流 | 按级别、来源、需求和关键词检索；应用筛选后查看结果，支持展开详细信息、加载更多和手动刷新 |
| OBS-08 | 日志需求分组 | 按需求聚合近期日志，点击分组进入该需求的过滤结果；不依赖用户手动重复输入 |
| OBS-09 | 告警规则 | 创建、查看、启停和删除规则，配置名称、指标、比较关系、阈值、观察窗口与适用范围 |
| OBS-10 | 告警评估与历史 | 定期评估并支持立即评估；展示触发中与已恢复状态、实际值、触发及恢复时间，不重复生成同一活动告警 |
| OBS-11 | 通知送达 | 将有效告警发往已配置渠道，展示送达状态、尝试次数和失败原因；服务未接入时明确显示未配置 |

OBS-01 至 OBS-10 为保留；OBS-11 为补齐，通知记录与真实通知渠道的可用性要分别验收。

## 指标口径

| 指标 | 定义与展示要求 |
| --- | --- |
| 调用量 | 选定范围与窗口内的实际记录，区分成功和失败 |
| 模型消耗 | 分列输入、输出及合计；没有消耗数据不推算成零 |
| 成功率 | 成功调用占有明确结果调用的比例；无样本显示暂无数据 |
| 延迟 | 标明平均值或高分位值、时间单位与统计样本 |
| 估算费用 | 根据可用单价和用量估算，明确不是实际账单；小额保留足够精度 |
| 需求归因 | 只将可以关联的记录计入需求；未知归属单独显示 |
| 自动化成功率 | 区分任务成功、验证通过、交付完成，不能混用口径 |

告警支持成功率、错误数、高分位延迟、费用、调用量等已有指标。阈值与窗口必须有效；用户配置的是规则，页面不能把规则存在当成告警已经触发。

## 更新行为

总览和用量可定期更新并提供手动刷新。切换窗口后，以新窗口结果到达作为页面数据切换时点。日志与长轨迹浏览保持用户阅读位置，不强行自动翻页。更新中断保留旧结果、标明过期时间，不能继续显示“实时”。

轨迹展示产品实际记录的活动和公开摘要，不承诺获得所有智能体内部推演过程。仅按时间接近的需求归因标为“近似”，不能当作确定因果证据。

## 空态与错误

没有调用记录、无筛选命中、采集未接入、服务不可用、授权不足分别呈现。零次数只用于确认没有记录的情况。敏感凭证、个人隐私和不适合共享的原始内容应在显示与通知前隐去。

## 验收

1. 7／30／90 天切换后所有卡片和明细使用同一窗口。
2. 按需求查看的费用能对上同范围明细，无法归因的记录不硬塞给某个需求。
3. 日志筛选与加载更多同时保留筛选条件；空结果提供清除筛选入口。
4. 连续评估同一个仍在触发的规则不会不断新增告警；恢复后记录恢复时间。
5. 通知失败能查到状态，不能显示成已送达。
6. 轨迹缺失、近似关联、过期数据在界面中明确可辨认。

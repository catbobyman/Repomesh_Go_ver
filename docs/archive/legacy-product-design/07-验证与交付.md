# 07 · 验证与交付

## 目标

让每项交付都有固定的候选范围、明确判据、可核对的验证结果和实际完成事实。

## 验证功能

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| VAL-01 | 候选审阅 | 展示仓库变更清单、变化规模、候选版本、本次任务及审阅意见，支持问题与返工记录 |
| VAL-02 | 独立复验 | 在独立于执行成员工作现场的环境中核验范围、基准及冻结检查项；成员自测和队长接受不能替代复验 |
| VAL-03 | 分层测试计划 | 按任务自测、单仓验证、跨仓联调、端到端验收组织检查；显示必需项、选做项、进度、失败和未执行项 |
| VAL-04 | 不可变验证快照 | 固定每个参与仓库的候选版本及验证结论；任一候选或判据变化后需要新的适用证据 |
| VAL-05 | 证据浏览 | 展示检查名称、执行结果、退出状态、时间、输出摘要、成果数量、风险和阻塞；缺失项显式列出 |
| VAL-06 | 独立测试团队 | 由测试资产仓团队承接跨仓联调，保存场景、环境定义和本轮证据；不替代业务仓的单仓检查 |
| VAL-07 | 联调轮管理 | 由组织负责人冻结多仓候选组合与判据，测试团队在一次性环境中执行，记录通过、失败或条件阻塞，结束后清理 |

VAL-01、VAL-02、VAL-04、VAL-05 为保留；VAL-03、VAL-06、VAL-07 的完整分层体验及环境兼容范围为补齐，已有部分路径不能等同于所有项目均可验证。

每个联调场景的最小证据包括执行步骤、退出结果、输出摘要和请求标识。判据由负责人确认，测试失败时先报告业务问题，不允许降低判据使结果变绿。环境不可用要记录为条件阻塞。

## 数据变更验证

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| DBV-01 | 数据影响声明 | 任务规划时明确是否涉及数据结构、历史数据处理或查询行为，记录影响对象和必需检查；成员不能自行缩小声明 |
| DBV-02 | 测试交接 | 候选固定后交给测试团队，展示候选版本、测试资产仓、必需检查、受影响数据对象和证据关联 |
| DBV-03 | 测试计划与返工 | 测试队长根据声明选择场景；遗漏必需项时要求补齐；测试团队失败阻塞交付，不直接冒充业务任务失败 |
| DBV-04 | 隔离数据环境验证 | 在获准的隔离环境中依次完成结构变更、历史数据处理、兼容及业务校验；第一项失败即停止后续检查 |
| DBV-05 | 环境清理与证据生效 | 成功与失败都执行清理；失败清理可单独重试；只有验证通过且清理完成的匹配证据可用于交付 |

以上为补齐范围：已有任务声明、交接状态与验证流程，真实外部数据服务接入仍需独立验收。没有真实服务时显示“外部环境不可用”，不能把演示通过当成真实验收。

页面状态包括测试计划已生成、测试团队执行中、需要返工、证据完成、环境准备中、验证中、通过、失败、清理中、清理完成、外部条件阻塞。未声明数据影响的任务不凭标题猜测后自动展示为数据任务。

## 交付功能

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| DLV-01 | 交付组与轮次 | 一轮集中展示各仓候选、验证快照、目标分支、交付阶段及历史决定；可查看旧轮次 |
| DLV-02 | 候选评审请求 | 为每个参与仓库形成可审阅的候选请求，展示标题、来源需求、验证摘要、关联请求和外部链接 |
| DLV-03 | 外部检查与评审跟踪 | 观察必需检查、人工评审、分支状态和候选变化；接入失败与检查失败分别展示 |
| DLV-04 | 逐项交付门禁 | 明确列出验证、必要检查、批准数、上游依赖、冲突、恢复事项、候选有效性等条件，不满足时显示每个原因 |
| DLV-05 | 受控合入 | 按组织及仓库策略进行人工批准或已启用的自动推进；自动方式只有明确配置并满足全部条件才生效 |
| DLV-06 | 跨仓顺序交付 | 先交付提供方，再交付依赖方；上游未确认完成时下游不能前进；一仓完成不代表整组完成 |
| DLV-07 | 实际状态对齐 | 外部受理操作后显示“等待确认”，观察到实际完成才显示成功；刷新、服务恢复后继续核对，避免重复交付 |
| DLV-08 | 交付证据包 | 汇总需求、规格、范围、计划、候选组合、验证、人工决定、交付结果和恢复路径，支持查看与授权导出 |

DLV-01 至 DLV-07 为保留；DLV-08 的完整一键导出体验为补齐，现有分散证据应保留。

## 交付失败与边界

检查失败产生返工或恢复事项，新候选必须重新验证。目标分支发生变化或候选冲突时，关闭交付门禁。部分仓库完成后其余失败，显示“部分完成／等待恢复”，不能显示整组成功。

本册的“完成”指确认的仓库交付结果。候选就绪、评审请求已创建、仓库合入与生产环境发布必须使用不同标签。

## 验收

1. 缺少任一必需检查、实际批准或上游完成事实时，不允许合入。
2. 旧候选通过的验证不能批准新候选；跨仓组合也必须完全匹配。
3. 队长接受但复验失败时，任务保持可解释的失败或返工状态。
4. 数据验证失败与清理失败分别呈现；清理重试不重复整个验证。
5. 外部合入仅被受理时仍为等待确认；全部仓库真实完成后才整组完成。
6. 证据包能够反查每项结论的任务、版本、操作者和时间。

# 12 · 扩展能力与边界

## 范围说明

本册保留项目材料中明确提出、尚不宜当作当前完整产品承诺的能力。它们属于重写时需要评审的全量需求，不默认塞进首版，也不因尚未完成而从产品范围中消失。

## 仓库内发起需求

| 编号 | 功能 | 预期行为 |
| --- | --- | --- |
| EXT-01 | 仓库内提及助手 | 在已授权仓库的议题中提及 RepoMesh，发起问题、计划或状态查询；普通提问不会自动开始修改 |
| EXT-02 | 从入口发现多仓范围 | 议题所在仓库只作为线索，不等于最终交付范围；仍需发现、举证和范围确认 |
| EXT-03 | 确认指定计划并开工 | 用户先明确批准某个计划版本的范围，再明确要求执行；旧版本、权限不足或范围缺失时拒绝 |
| EXT-04 | 状态评论与检查卡 | 在同一议题持续更新当前阶段、计划、范围、任务数、阻塞及工作台链接，避免频繁刷屏 |
| EXT-05 | 仓库对话绑定 | 外部议题与工作台需求保持关联；外部消息删除或平台暂时不可用不丢失正式交付记录 |
| EXT-06 | 评审、修复与重试指令 | 后续支持对当前候选进行评审、修复、重试、取消、修改计划及查看证据；影响跨仓时先请求新范围确认 |
| EXT-07 | 专用需求入口 | 允许组织使用仅接收需求的仓库，该仓不自动成为交付对象；管理入口和自动创建属于后续能力 |
| EXT-08 | 多托管平台入口 | 首期面向 GitHub，其他托管平台在相同产品规则下逐步接入，不能将仓库扫描支持等同于原生入口已支持 |

这些均为扩展功能。对话提供提问、规划、批准范围、执行、查询状态五类明确动作。最终治理审批继续在具备真实人工身份与授权的入口完成。

## 仓库入口规则

- 功能按部署、工作区和仓库启停，默认关闭；关闭后停止接受新请求，既有交付仍能从工作台处理。
- 一次明确执行指令只启动一次工作；同一议题首期最多一个活跃交付。
- 编辑历史评论不自动重放执行；助手自身回复不触发新的任务。
- 必需仓库未授权时保留其证据并阻止开工，不静默缩小范围。
- 当前候选评审及修复绑定其版本；版本变化后先重新确认。
- 外部平台仅显示正式记录的状态，不依据聊天语气推断完成。

## 其他已提出的扩展

| 编号 | 功能 | 预期价值与边界 |
| --- | --- | --- |
| EXT-09 | 企业身份与账户完善 | 企业统一登录、账户停用、密码恢复与会话治理；与现有本地账户共用清晰的业务授权规则 |
| EXT-10 | 生产环境交付 | 在仓库成果之上管理发布候选、环境晋级、发布前后验证、灰度与恢复；必须独立定义环境、权限、观测及失败判据 |
| EXT-11 | 交付证据导出 | 面向发布评审和审计导出完整证据集合；导出按权限脱敏，并标明生成时间与候选版本 |
| EXT-12 | 团队与资产退役 | 对不再使用的团队、房间和仓库建立停用与保留历史的流程；在途工作未处理时不直接删除 |

EXT-10 来源于早期产品愿景，现有合入与回滚能力不能作为真实生产发布已经实现的证据。EXT-12 是既有材料明确指出的缺口，不预设可以立即删除长期组织。

## 重写前需要确认的产品决策

| 议题 | 当前基线 | 待确认内容 |
| --- | --- | --- |
| 首版范围 | 优先形成可验证的核心交付闭环 | 补齐项与扩展项的具体发布批次 |
| 默认监管 | 三档可选且开工前明确 | 新工作区采用哪档默认值，不沿用无提示的自动行为 |
| 运行中改监管 | 属于补齐 | 对在途任务和已完成步骤如何生效 |
| 数据验证服务 | 流程已定义，实际可用性单独验收 | 获准服务、测试数据、配额和清理约束 |
| 通知渠道 | 有送达与重试要求 | 使用哪些组织已有渠道及默认通知对象 |
| 保留周期 | 不同资料分别配置 | 组织要求与审计保留期限 |
| 生产发布 | 扩展能力 | 支持哪些环境，谁有发布和恢复权 |
| 团队退役 | 保留历史，不承诺直接删除 | 停用、转交、归档和恢复的完整规则 |

## 扩展验收

仓库原生入口启用后，应独立验收从提问、规划、确认到执行及状态回写；功能关闭时既有工作仍可管理。生产发布及企业身份必须有真实环境证据，不能只凭演示原型或本地模拟宣称完成。

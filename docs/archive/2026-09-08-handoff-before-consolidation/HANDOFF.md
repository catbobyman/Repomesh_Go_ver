## 2. 已确认组织、入口与资源边界

- 使用 agentscope-ai/AgentTeams；每个长期多仓项目独立实例、一个 Manager，每仓长期 Team 和 Leader。
- 所有新 issue，无论单仓还是跨仓，都先进入独立的 Manager 主房间，由项目现有 Manager 接收并始终承担 issue 总责，再按范围委派一个或多个 Leader。Leader 负责仓库工作；用户在 Manager 主房间查看反馈和结果。
- 每条 issue 使用独立主房间和所需仓库子房间，各 Agent 有自己的 session；复用 Manager 身份不混用不同 issue 的上下文。追加消息、重试和重复事件返回原主房间。
- 全部 issue 的主房间与子房间如何映射原生资源/session、触发消息和恢复仍待验证。邀请或加入房间不等于模型 session 已建立；建房失败保留 issue，核查已有结果后幂等重试。
- 保存项目或完成配置不创建实例；首条 issue 正式提交并持久化后才准备实例，Ready 后为该 issue 创建独立主房间并交给 Manager。失败保留 issue，幂等重试；后续复用或恢复原实例。
- 一期最多一台服务器，项目实例的 Controller、Matrix、存储和网关分别配置。RepoMesh 统一控制全局容量与项目额度。
- Worker 单活跃任务，每次 Attempt 独立 clone、分支、构建目录及记录。长期身份、运行进程、任务副本和权限分别管理。
- Agent 不直接持有宿主 Docker socket；普通容器不承诺 VM 或恶意多租户隔离。临时资源回收前保存必要产物，关键数据需要服务器外备份。
- 团队和验证按 Skill 组织工作；Leader／验证负责人动态请求 Worker，优先复用合适空闲成员。数量可在设置中调整，默认 1，沿用 A1 的团队 Worker 并发上限含义。RepoMesh 实际分配、创建和启动，仍检查全局容量、项目额度、独立性及有效权限。
- 优先完成已有候选的验证、必要诊断和收尾，同级按等待顺序安排。Worker 失联时核查旧执行停止或失去写入能力后再替补；验证负责人不可用时 Manager 代行协调。身份和运行资源分开回收，详见团队执行策略。
- 记录 Skill 版本，落实到本次版本化计划和必检清单；Skill 更新不静默替换在途计划或验收要求。

## 4. 计划版本、获准与生效

1. 变更针对明确版本，展示差异、原因、依赖、范围和上限，保留旧版本。
2. 按自动化模式判断许可，两个模式共用实际执行约束。
3. 已获准范围和上限内的 Loop 自动运行；默认修复 3 轮、诊断补证 2 轮、环境恢复 2 次，写入具体计划；预算或时限先到先停，换计划不清零累计消耗。
4. 获准与生效分开。应用时按受影响的上游 Project 暂停新派工，等待在途及 submitted 结果处理到可重规划状态，再核对、应用和读回。
5. 拒绝、冲突、失败和不确定结果保留历史；写入不确定时先核查，不直接覆盖最新状态。
6. RepoMesh 实际控制计划应用和任务启动；不能只依靠聊天、Skill 或提示词。

首期用户只通过自然语言调整编排，由 Manager 形成版本化提案。Graph／Loop 采用插件形式，支持顺序、并行、汇合与有界 Loop，具体 D1—D7 见 ADR-0007。连续两轮相同失败且无新增有效证据时结束当前循环；新策略走版本化变更。独立且获准的工作可继续，变更应用仍服从受影响上游 Project 的暂停边界。

直接编辑节点、属性、连线及拖拽编排为后续待办。插件形式不代表原生能力已经验证，暂停不停止在途任务。

## 5. 验证节点与人员职责

首次计划记录固定基线，每次验证绑定完整 commit 组合，包括未改动但参与联调的仓库。各验证 Attempt 使用独立环境、配置和 mock 数据；Leader 提供运行说明、mock 数据及其使用说明，验证侧组织准备并核对实际运行版本。失败先保留日志和现场，按固定清单重建；完成并保存证据后释放资源，详见联调环境设计。

候选变化重新判断证据有效性；验证环境不向业务仓推送修复。采用 mock 数据不自动证明未实际覆盖的真实链路。

- 节点输入：检查范围及必检项、适用验收和计划版本、Skill 版本及业务解释来源、固定组合、验证前提、授权与预算等约束。
- 最小证据：检查归属、实际验证对象、判定依据、执行证据和检查结论；附件按页面、接口、构建及阻塞等类型保留。
- 单项结果：通过、业务缺陷、环境阻塞、需求待澄清、暂无法判定。测试数据问题属于环境阻塞原因；缺少证据不直接证明业务缺陷。
- 已证实违反要求即为业务缺陷，具体仓库可以待定位。业务解释按模式补充，解释明确后仍需真实检查证据。
- 全部约定必检项具有适用于当前固定组合的有效通过证据，节点才通过。执行结束、提交和跳过都不代表通过。
- 可拆多个专项节点，各自明确覆盖范围，issue 汇总验收覆盖和未通过原因。节点通过不等于 issue 已完成。

项目验证小组默认不启用，项目管理员或获授配置权限的人可以修改并留记录；启用时设固定验证负责人，未启用时 Manager 组织具备能力和有效权限的 Worker。正式验证者未参与本轮被测业务改动，业务作者可自测和提供脚本。

各仓 Leader 提供契约、范围、风险及已有测试；验证负责人编制必检清单；Manager 核对覆盖、依赖和预算并纳入计划；Worker 编写或复用测试、执行并提交初判；负责人复核采纳，Manager 汇总。未启用小组时，Manager 组织起草并承担复核。上述是 Agent 内部分工。

验证侧提供证据和初步归属，仓库 Leader 定位；Manager 协调分歧和补充诊断。业务 Team 修复，验证侧组织独立 Worker 针对新固定组合重验。诊断和重验遵守有效计划及额度。

关闭小组后停止接新工作：未启动任务交回 Manager，在途 Attempt 收尾，submitted 结果继续核对；从“停用中”到“已停用”，保留真实结果及历史。长时间未收尾按任务超时处理，显示停用受阻及原因；重新启用后恢复接新，在途继续，不自动抢回已交给 Manager 的任务或复活已终止 Attempt。

### PR 与人工审查

各仓 Leader 初审形成有明确范围和自测记录的候选后创建 draft PR，跨仓验证可随后继续。默认一条 issue 在一个仓库持续更新同一个 PR，保留 commit 和证据关系。全部必检项对当前组合有效通过、内部复核完成且必需仓库检查满足后，Manager 推荐正式审查；首期由人将 GitHub draft 转为正式 PR。反馈回到原 issue，按模式和有效计划处理。

E1—E5 的审查规则继续有效，合并顺序、完成条件和恢复按已确认 CS9—CS12 处理，详见 PR 审查与 ChangeSet 设计。

### ChangeSet 归属与历史

这里的 Issue 指 RepoMesh 内部的一条统一需求事项，可以涉及一个或多个仓库；它与 GitHub 单仓 issue 分开，可关联零到多条 GitHub issue，标明来源或跟踪关系；重复导入查已有映射，首期不默认启用外部创建、评论、同步或关闭操作，见 ADR-0002 和 CS1。

issue 正式提交并持久化时建立对应主 ChangeSet，允许暂时没有候选、组合或 PR；后续继续关联记录，重复事件与恢复复用既有归属。ChangeSet 同时服务于 Agent 查看变更和溯源相关产物、依据与交付历史。Agent 先读带引用的摘要，再按需查询关联的结构化记录及原始证据；结论可定位来源，缺失证据如实显示。Issue 与主 ChangeSet 已确认原子登记，具体事务及查询接口待实现细化，不改变实例准备时机。Agent 默认查当前 ChangeSet，可按既有权限查同项目相关历史，不默认开放跨项目查询。

ChangeSet 确定本次变更归属，串联 issue、仓库、PR、Candidate、Delivery Combination 和交付历史。沿用已有候选及交付组合表达多轮产物，不另定义一套重复的候选模型。Candidate 正式提交即收录，关联产物版本及来源 Task／Attempt；后续未被接受也保留检查结果、原因和历史，修复后新建候选而不覆盖旧记录。收录不等于检查接受，提交不等于交付，各仓成功不等于组合通过。组合变化仍需重新判断证据适用性。

修复和重试保留同一 ChangeSet，各逻辑操作独立记录；重试核查既有结果，新变更另行记录。外部结果未知时先核查，不能仅凭本地记录认定成功。已确认同一操作标识绑定目标及输入、同标识不同输入拒绝、并发校验目标版本和冲突操作串行处理。精确字段、工具接口和运行适配仍待细化；CS1—CS14 产品规则已确认，不含已延后的 H—K。

正式交付组合由 Manager 从已内部初审接受的业务候选中按验证范围、前提和有效计划选定，未改动仓库固定基线。仓库版本变化建立新组合；仅验证上下文变化时新增验证记录并重新判断证据。执行、验证、交付进展分别汇总，PR 与真实 commit 及合并结果关联。

完成条件按 CS9：约定交付物、验收及必做事项完成，代码变更的所有必需 PR 已人工合并，最终实际组合证据有效；部署另记。按兼容性选合并顺序，部分合并后依据实际版本推进剩余工作，不自动撤销成功部分。取消未合并 PR 留原记录；撤销已合并代码由人发起关联恢复事项，仓库 Team 出撤销 PR、人合并；首期部署和数据恢复由有权限的人执行并记录。

本轮修复复用原 ChangeSet，完成后新增范围建立关联的新 Issue／ChangeSet，首期无嵌套 ChangeSet。项目存续期保留归属、版本关联、决定和操作结果，必要验收证据随交付档案保存，临时材料按策略清理并标记可用性。

## 4. 首批推荐范围和验收场景

推荐先设计登录／权限、项目保存、手动选仓创建 Issue、列表与详情；然后开发真实持久化链路，再接运行准备和 Manager，随后推进分析与受控执行。这是上一轮建议的排期，不恢复旧 Prompt 中“先做 MCP／先做分析插件”的任务顺序，也不要求取消既有自动准备设计。

第一批若暂未接通运行端，页面应显示真实的未接入／未就绪情况；业务与准备待办可以有持久事实，但不能伪装 Manager 已接手。真实自动准备链路的产品验收仍需下一批完成。

页面／接口设计至少覆盖：

1. 无项目进入、项目待配置、账号有读取资格但 App 能力不足、外部核查未知；不把它们压成一个“未授权”。
2. 保存项目不建 Issue、不启动实例；所选仓库完整保留，不因刷新或分页自动扩仓、删仓。
3. 创建 Issue 默认新会话；选择已有会话后失权或关联失效，提示实际错误，不静默换会话。
4. 未提交前取消不建项；已发请求后超时、关页面、取消等待不代表回滚，再进入时查询原创建操作。
5. 原操作重试得到原结果；同标题的明确新工作仍可独立创建；404 查询结果不触发盲目换键重建。
6. 刷新仍显示持久结果；切换 Issue 后旧响应不覆盖新页面；SSE 断流显示可能过期并按契约补查。
7. 创建成功但 Manager 未就绪或准备失败，业务记录仍存在；没有真实房间依据时不显示可进入状态。
8. 当前失权时清理敏感页面数据，查询／订阅均由后端核权，隐藏按钮不能替代服务端权限检查。

P06 另覆盖多 Issue 目标澄清、两条连续消息中前条结果未知、晚到回复仍保持原归属；P07 另覆盖未选仓可分析、部分扫描、应用不清掉手动选择、输入变化、跨用户／项目拒绝及失败手动建项。

## 5. 文件职责与交接方式

页面／接口负责人主维护 [页面专题](../../current/conversation-issue-separation-design.md)、[消息目标专题](../../current/conversation-message-target-design.md)、[创建接口契约](../../current/issue-page-create-api-contract.md)及本文件；项目入口、配置、仓库分析的页面／浏览器接口章节按涉及场景补充。优先更新现有专题，必要时才新增独立协议文档。

后端负责人维护内部数据约束、事务、可信运行接入、完整 MCP／Python Schema 和执行恢复设计。REST／SSE 由页面侧维护单一字段基线，后端审查可实现性；MCP 业务语义双方对齐，机器 Schema 与可信传输由后端主维护，不复制两套冲突字段。仓库事项基数、房间拓扑、创建原子范围须共同核对。

新任务开始时先明确实际文件编辑归属。本文不指定旧任务 ID，不联系旧协作者，不追加旧通信日志或自动创建新任务。旧 Prompt 和原始通信仅为来源；用户实际新任务授权优先。

每项交接记录具体场景、采用基线、待细化点、理由／代价、修改位置、对后端的要求及待验证能力。标为“设计完成”必须同时具备正常、失败、未知和恢复路径，不以页面截图或模拟成功判定真实接口完成。

## 6. 开始对应批次开发的设计条件

- 该批次的页面流程与状态表完整，用户动作、允许条件、不可用原因和结果去向明确。
- 所用 REST／SSE 契约有唯一来源，输入输出／错误／幂等／修订与后端一致。
- 影响该批次的对象关系和最小数据约束已与后端收口；无须冻结后续全部数据库表。
- 失败与恢复验收用例可执行，明确哪些能力尚未接入和该批次验收到哪里。

以上是工程就绪条件，不是新增人工开工审批流程。当前这次任务仅编写交接；后续设计或实现范围以用户实际任务为准。Skill、直接编辑图、后续审批和历史分析继续暂缓；YOLO 不放大权限，也不授予自动 Git 合并权。

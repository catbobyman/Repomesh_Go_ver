| 请求超时 | 每个请求 15 秒上下文超时，见 [projects.go](../../internal/web/projects.go) 第 169 行。 |
| Origin | `POST` 与 `PATCH` 必须携带单值 `Origin` 且等于部署 origin，否则 403 `ORIGIN_REJECTED`。 |
| CSRF | 写操作要求 `X-CSRF-Token` 等于当前会话 `csrfToken`；读取不要求，见 [project_access.go](../../internal/access/project_access.go) 第 54 行。 |
| 响应头 | 统一 `Cache-Control: no-store` 与 `Referrer-Policy: no-referrer`。 |
| 错误体 | `{"error":{"code","message","fieldErrors","requestId"}}`，由 [projects.go](../../internal/web/projects.go) 第 206 行的 `writeProjectError` 生成；未识别错误一律 503 `RESULT_UNCONFIRMED`，`requestId` 是随机值，不等于业务操作身份。 |
| 请求体 | 只接受 `application/json`（可带 `charset=utf-8`），上限 256 KiB；过大 413 `REQUEST_TOO_LARGE`，读取失败 400 `INVALID_JSON`，内容类型不符 415 `UNSUPPORTED_MEDIA_TYPE`，见 [projects.go](../../internal/web/projects.go) 第 182 行。合法 JSON 的未知字段、类型或长度错误统一 422 `VALIDATION_FAILED` 并携带 `fieldErrors`。 |

| 作用域 | 创建为 `(actor, project_create, key)`；更新为 `(actor, project, project_update, key)`。`schemaVersion` 只用于解释原输入，不进入作用域。 |
| 事务设置 | 每次写事务为 `READ COMMITTED`，并设置 `lock_timeout='2s'`、`statement_timeout='5s'`、`synchronous_commit=on`，见 [storage.go](../../internal/projects/storage.go) 第 17 行。 |
| 身份锁序 | 每条路径先锁绑定、再锁会话、最后锁账号，见 [project_access.go](../../internal/access/project_access.go) 第 67 行；随后才进入各业务表。逐路径顺序见下表。 |

| --- | --- |

## HTTP API

### POST /api/projects

#### 调用方与授权

已登录用户创建项目。owner 固定为当前认证 actor；不接受客户端 owner、权限、分支或 `startRuntime` 字段。

#### 输入

| 字段 | 类型 | 必填 | 约束 | 含义 |
| --- | --- | --- | --- | --- |
| `name` | string | 是 | 非空白，最多 200 个 Unicode 标量 | 项目名称。 |
| `purpose` | string | 是 | 非空白，最多 20000 个 Unicode 标量 | 项目用途。 |
| `repositoryIds` | string[] | 是 | 非空、去重、最多 100 项，每项形如 `repo_` 加 20 位数字 | 初始仓库范围，必须来自当前凭据下的发现结果。 |
| `configuration` | object | 否 | 提供时必须恰好包含 `modelProfile` 与 `executionProfile` 两项引用 | 省略等价两项 `{"mode":"inherit"}`。 |

引用形状只允许 `{"mode":"inherit"}` 或 `{"mode":"reference","id":"profile_id"}`；`inherit` 不允许带 `id`，`reference` 必须带 `id`，不接受 null、Key、供应商地址、预算数值或任意命令，见 [input.go](../../internal/projects/input.go) 第 139 行。解析与规范化见 [input.go](../../internal/projects/input.go) 第 50 行；`repositoryIds` 在规范化时排序，而 `exact_input` 保留提交顺序。

#### 行为

1. 校验并规范化输入；任一仓库 ID 不在当前发现范围内返回 404 `RESOURCE_NOT_FOUND`，见 [project_access.go](../../internal/access/project_access.go) 第 115 行。
2. 逐仓调用 GitHub 观察用户读权；`denied` 返回 404，`unknown` 或凭据不可用返回 503 `AUTHORIZATION_UNCONFIRMED`，见 [storage.go](../../internal/projects/storage.go) 第 231 行。
3. 在写事务中复核连接修订、访问代次与观察时效（60 秒窗口），随后把项目、范围、固定配置修订、原操作输入与回执写入同一事务，见 [service.go](../../internal/projects/service.go) 第 102 行至第 195 行。
4. 不产出会话、Issue 或运行准备待办；App 或模型配置缺失不妨碍保存待配置项目。

#### 返回

首次成功 `201 Created`，同键同输入重放 `200 OK`：

```json
{"projectCreationId":"b3e58aa5-7dc4-4c95-97bc-4bead37d13bc","status":"committed","projectId":"UUID","projectRevision":"UUID","createdAt":"2026-09-10T00:00:00Z","links":{"project":"/api/projects/UUID","operation":"/api/project-creations/b3e58aa5-7dc4-4c95-97bc-4bead37d13bc"}}
```

回执由原操作行生成，见 [storage.go](../../internal/projects/storage.go) 第 127 行；`projectRevision` 与 `createdAt` 固定为原提交值。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 400 | `INVALID_JSON`、`INVALID_IDEMPOTENCY_KEY` | 请求体不是对象；幂等头缺失或重复。 |
| 403 | `ORIGIN_REJECTED` | Origin 缺失或不匹配。 |
| 413 | `REQUEST_TOO_LARGE` | 请求体超过 256 KiB。 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 请求体不是 JSON。 |
| 422 | `VALIDATION_FAILED` | 字段缺失、未知字段、长度或集合约束不满足。 |
| 404 | `RESOURCE_NOT_FOUND` | 仓库不在当前范围内，或用户确认无权。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同键不同规范化输入。 |
| 503 | `AUTHORIZATION_UNCONFIRMED`、`RESULT_UNCONFIRMED` | 权限核查不确定；数据库、锁或提交结果不可用。 |

#### 并发与重放

两个并发请求使用同一键时，只有一行原操作能插入成功；落败者在同一事务里读到赢家并按原输入重放，见 [service.go](../../internal/projects/service.go) 第 126 行。提交成功后 `FirstCommit` 决定 201 与 200 的区别。同键不同输入返回 409，不改绑原操作；旧回执不会被后续项目修订影响。

#### 设计理由

项目、初始范围、固定配置与回执同事务提交，用户双击或网络重试得到的是同一个项目，而不是两个同名任务。初始范围必须逐仓真实核权，避免把“名字看起来对”当成可读。

### GET /api/project-creations/{projectCreationId}

#### 调用方与授权

创建恢复页与脚本核查。只允许原操作者查询自己账号下的操作；项目当前是否可读另行判断。

#### 输入

路径 `projectCreationId` 为 UUID 形状；非 UUID 直接按 404 处理，见 [service.go](../../internal/projects/service.go) 第 421 行。

#### 返回

`200 OK`，与创建回执同形。已提交操作返回固定 `projectRevision`、`createdAt` 与 `links`。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 404 | `PROJECT_CREATION_NOT_FOUND` | 非 UUID、无该操作、跨主体或原项目已不可读。 |
| 410 | `PROJECT_CREATION_RESULT_REMOVED` | 回执已按保留策略清理。 |
| 401、503 | `AUTHENTICATION_REQUIRED`、`RESULT_UNCONFIRMED` | 会话失效；数据库不可用。 |

#### 并发与重放

查询只读、不写、不重执行原创建。404 只表示“当前没有可见提交”，不表示原请求一定失败；不得换键自动重建。同键重放优先于比较新正文，见 [storage.go](../../internal/projects/storage.go) 第 99 行。

#### 设计理由

把恢复查询与创建分开，客户端在响应丢失后可以先核查事实，再决定继续或修复，而不是靠猜。

### PATCH /api/projects/{projectId}

#### 调用方与授权

项目 owner 编辑资料、增加仓库或显式更新配置引用。

#### 输入

| 字段 | 类型 | 必填 | 约束 | 含义 |
| --- | --- | --- | --- | --- |
| `expectedProjectRevision` | string | 是 | UUID 形状 | 客户端读到的当前修订，用于并发冲突检测。 |
| `name` | string | 否 | 同创建 | 新名称。 |
| `purpose` | string | 否 | 同创建 | 新用途。 |
| `repositoryIdsToAdd` | string[] | 否 | 去重、最多 100 项，最终总范围不得超过 100 | 增量仓库集合；已存在的 ID 按集合幂等忽略。 |
| `configuration` | object | 否 | 提供时是完整两项引用 | 显式重新解析并固定版本；省略保留原值。 |

除 `expectedProjectRevision` 外必须至少提供一个字段，否则 422，见 [input.go](../../internal/projects/input.go) 第 88 行。没有删除仓库或整体替换范围的字段。

#### 返回

`200 OK`：

```json
{"updateId":"30658f09-049a-4e8e-b44e-c7d0dfe78f5b","status":"committed","projectId":"UUID","projectRevision":"UUID","updatedAt":"2026-09-10T00:01:00Z","links":{"project":"/api/projects/UUID","operation":"/api/projects/UUID/updates/30658f09-049a-4e8e-b44e-c7d0dfe78f5b"}}
```

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 400 | `INVALID_JSON`、`INVALID_IDEMPOTENCY_KEY` | 请求体或幂等头非法。 |
| 404 | `RESOURCE_NOT_FOUND` | 项目不存在、非本 owner、已删除或路径非法。 |
| 409 | `PROJECT_REVISION_CONFLICT` | 新写请求的 `expectedProjectRevision` 不等于当前修订。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同键不同输入。 |
| 422 | `VALIDATION_FAILED` | 字段约束不满足，或新增后总范围超过 100。 |
| 503 | `AUTHORIZATION_UNCONFIRMED`、`RESULT_UNCONFIRMED` | 新增仓库核权不确定；数据库或提交不可用。 |

#### 并发与重放

已提交的原操作先重放，再判断新输入的 `expectedProjectRevision`，见 [service.go](../../internal/projects/service.go) 第 304 行至第 313 行；因此一次已经提交的更新不会因为项目随后变化而变成冲突。新写请求的预期修订过期返回 409，页面保留草稿并要求重新读取。仓库新增在事务外核权、事务内复核时效与连接修订；任一新增失败整次回滚。配置引用只要解析结果与当前固定值相同就不产生新修订；完全无变化时仍保存本次操作回执，见 [service.go](../../internal/projects/service.go) 第 343 行至第 375 行。

#### 设计理由

明确增量而不是整体替换，可以避免“当前可见列表”被误当成完整范围而删掉受限仓库。无变化保存也留回执，用户看到的是“这次点击已记录”，而不是安静的失败。

### GET /api/projects/{projectId}/updates/{updateId}

#### 调用方与授权

更新恢复页与脚本核查。只允许原操作者在原项目作用域内查询。

#### 输入

路径 `projectId` 与 `updateId`；任一形状非法按 404 处理，见 [service.go](../../internal/projects/service.go) 第 450 行。

#### 返回与错误

与更新回执同形；错误为 404 `PROJECT_UPDATE_NOT_FOUND`、410 `PROJECT_UPDATE_RESULT_REMOVED`、401 与 503。

#### 并发与重放

与创建查询相同：只读、不重执行；`projectRevision` 与 `updatedAt` 固定为该次提交值，不回填后续状态。

#### 设计理由

更新回执与当前项目快照分开保存，页面才能区分“这次提交了什么”和“项目现在是什么样”。

### GET /api/projects/{projectId}

#### 调用方与授权

项目概览与设置页。owner-only：非本 owner 与不存在的项目同样按 404 处理。

#### 输入

路径 `projectId`；形状非法返回 404 `RESOURCE_NOT_FOUND`，见 [service.go](../../internal/projects/service.go) 第 479 行。

#### 返回

`200 OK`：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id`、`name`、`purpose`、`projectRevision` | string | 稳定身份、资料与项目修订。 |
| `createdAt` | RFC3339 | 创建时间。 |
| `configuration.modelProfile`、`configuration.executionProfile` | object | 已保存的选择：`inherit` 或 `reference`。 |
| `configuration.effective` | object | 固定版本读取结果：`configurationRevision` 加 `modelProfileId`、`executionProfileId`、`workerConcurrency`、`budgetPolicyId`、`timeLimitPolicyId`、`verificationGroupEnabled`；对象内的引用与数值字段在无法解析时为 null，对象本身始终存在。null 不等于无限预算、0 额度、关闭校验或可执行。 |
| `configuration.checks` | object | 当前可用性观察：`allowed`、`denied` 或 `unknown` 加 `reasonCodes`、`observedAt`。 |
| `actions` | object | 当前实现固定 `{canEdit:true,canCreateIssue:false}`，见 [service.go](../../internal/projects/service.go) 第 504 行。 |
| `creationReadiness` | object | 由 `checks` 投影：`denied → restricted`、`unknown → unknown`、`allowed → ready`，见 [storage.go](../../internal/projects/storage.go) 第 441 行。 |

当前实现中 `checks` 在配置完整且秘密可用时仍返回 `denied` 并带 `MODEL_INTEGRATION_NOT_AVAILABLE` 或 `EXECUTION_INTEGRATION_NOT_AVAILABLE`，因为 Issue 与运行接入尚未实现，见 [storage.go](../../internal/projects/storage.go) 第 424 行。因此 `creationReadiness` 目前是 `restricted`；`ready` 分支只有后续批次真正接入运行后才有意义。

#### 错误与状态码

404 `RESOURCE_NOT_FOUND`（不存在、非本 owner、已删除、形状非法）；401 `AUTHENTICATION_REQUIRED`；503 `RESULT_UNCONFIRMED`。

#### 并发与重放

读取在锁主体后读取项目与固定配置；与更新并发时看到锁前或锁后的完整快照之一。读取不写业务行。

#### 设计理由

详情把“用户保存了什么选择”“实际固定的版本”和“当前可不可用”分开，用户能看出默认或秘密变化没有暗换已保存项目。

| --- | --- | --- | --- | --- |
| `q` | string | 否 | 空 | 最多 200 个 Unicode 标量，字面子串，大小写不敏感。 |
| `cursor` | string | 否 | 空 | 最多 128 字符。 |
| `limit` | integer | 否 | 50 | 1 到 100。 |

只允许这三个键且必须单值，见 [input.go](../../internal/projects/input.go) 第 323 行。

#### 返回

`200 OK`：`{"items":[{"id","name","projectRevision","createdAt"}],"nextCursor":null}`。排序固定为项目 ID 升序，无总数承诺，见 [service.go](../../internal/projects/service.go) 第 526 行。

#### 错误与状态码

400 `INVALID_CURSOR`（游标不存在或作用域不匹配）、409 `CURSOR_EXPIRED`（超过 10 分钟）、422 `VALIDATION_FAILED`、401、503。

#### 并发与重放

游标绑定 actor、查询文本与 `limit`，见 [storage.go](../../internal/projects/storage.go) 第 452 行。翻页期间新增较小 ID 的项目可能需要刷新；跨页不承诺快照一致。列表在需要下一页时写游标后提交。

#### 设计理由

游标绑定查询条件，避免把其他搜索或其他账号的位置当成授权；`items` 恒为数组，空结果与失败分开表达。

### GET /api/projects/{projectId}/repositories

#### 调用方与授权

项目概览的已保存范围展示与设置页分页。owner-only。

#### 输入

| 参数 | 类型 | 必填 | 默认 | 约束 |
| --- | --- | --- | --- | --- |
| `cursor` | string | 否 | 空 | 最多 128 字符，且绑定项目修订。 |
| `limit` | integer | 否 | 50 | 1 到 100。 |

#### 返回

`200 OK`：`{items,nextCursor,projectRevision,restrictedRepositoryCount}`。`items` 只包含本次允许披露的仓库；受限数量包含确认无权与核查未知，见 [service.go](../../internal/projects/service.go) 第 599 行。

#### 错误与状态码

409 `PROJECT_CONTEXT_CHANGED`（游标绑定的项目修订与当前不一致）、404 `RESOURCE_NOT_FOUND`、400 `INVALID_CURSOR`、409 `CURSOR_EXPIRED`、422、503 `AUTHORIZATION_UNCONFIRMED`。

#### 并发与重放

每页重新核权，不承诺外部权限跨页一致。范围变化使旧游标失效，页面从第一页重读，但不能据此删除用户的手动选择。

#### 设计理由

受限仓库的 ID 与名称不返回，只返回数量，避免用列表反推被隐藏的范围；完整范围仍保存在 `project_repositories` 中。

### GET /api/configuration-profiles

#### 调用方与授权

创建与设置页的配置选择器。只返回当前 actor 拥有的配置。

#### 输入

| 参数 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `kind` | string | 是 | `model` 或 `execution`，其他值 422。 |
| `cursor` | string | 否 | 最多 128 字符。 |
| `limit` | integer | 否 | 1 到 100，默认 50。 |

#### 返回

`200 OK`：`{"items":[{"id","name","availability":{"status","reasonCodes","observedAt"}}],"nextCursor":null,"defaultProfileId":null}`。`availability` 的取值规则：`enabled` 与 `parameters_complete` 不满足时 `denied` 并带 `MODEL_CONFIG_UNAVAILABLE` 或 `EXECUTION_CONFIG_UNAVAILABLE`；绑定秘密不可用时 `denied` 并带 `MODEL_SECRET_UNAVAILABLE` 或 `EXECUTION_SECRET_UNAVAILABLE`；`model` 类型没有秘密时 `denied` 并带 `MODEL_CONFIG_MISSING`；否则 `allowed`。实现见 [service.go](../../internal/projects/service.go) 第 705 行至第 723 行。

#### 错误与状态码

422 `VALIDATION_FAILED`（`kind` 缺失或非法、游标过长、`limit` 越界）、400 `INVALID_CURSOR`、409 `CURSOR_EXPIRED`、401、503。

#### 并发与重放

读取前取 `repomesh_projects.catalog` 行的 `FOR SHARE` 锁，使默认缺省与双引用绑定有确定事务边界，见 [storage.go](../../internal/projects/storage.go) 第 258 行。检查失败整体返回 503，不写游标。

#### 设计理由

配置列表只暴露“可引用性”，不泄露秘密内容；某个配置暂不可用仍可作为待修复引用保存，不等于允许执行。

## 目标解析

B02 的 `GET /api/auth/attempts/{id}` 需要把 Destination 解析成站内地址，项目模块提供其中四项，见 [service.go](../../internal/projects/service.go) 第 739 行：

| Destination | 解析结果 | 校验 |
| --- | --- | --- |
| `{"kind":"project"}` | `/projects/{projectId}` | 项目存在、属于当前 actor、未删除；否则 404，尝试查询把 `nextPage` 退回 `/`。 |
| `{"kind":"operation","operationKind":"project_create"}` | `/project-creations/{operationId}` | 只校验键形状，不要求项目已存在。 |
| `{"kind":"operation","operationKind":"project_update"}` | `/projects/{projectId}/updates/{operationId}` | 项目存在、属于当前 actor、未删除。 |

其他 Destination 由 B04 的模型模块或后续批次解析；没有解析器的类型 `nextPage` 为 null，页面停留在结果页并重新核对。

实现与采用稿之间有一处需要后续同步的差异：认证稿的 Destination 表把 `{"kind":"project"}` 的返回路由写为 `/projects/{projectId}/issues`，而当前实现返回 `/projects/{projectId}`（项目概览页），见 [service.go](../../internal/projects/service.go) 第 751 行。首批尚未实现 Issue 列表路由（浏览器契约 §8 属 B07 范围），实现落在已存在的项目页面上。本文件如实记录该差异；修改任一方向都需要同步拥有该契约的专题，不在本目录单方面改写采用稿。

## 数据库表

### repomesh_projects.catalog

#### 用途与写入者

## 事务与恢复

| 场景 | 期望行为 | 依据 |
| --- | --- | --- |
| 同键同输入并发创建 | 只有一个项目；落败者重放赢家回执 | [service.go](../../internal/projects/service.go) 第 126 行 |
| 同键不同输入 | 409 `IDEMPOTENCY_CONFLICT`，不改绑原操作 | [storage.go](../../internal/projects/storage.go) 第 99 行 |
| 创建成功但响应丢失 | 同键重放返回原 `projectId`、`projectRevision` 与 `createdAt` | 第 127 行 |
| 更新成功但响应丢失 | 同键重放优先于修订冲突判断 | [service.go](../../internal/projects/service.go) 第 304 行 |
| 新写请求携带旧修订 | 409 `PROJECT_REVISION_CONFLICT`，草稿保留 | 第 314 行 |
| 事务内某步失败 | 项目、范围、配置与回执一起回滚 | 延迟约束与单事务写入 |
| 无变化更新 | 不产生新项目修订，仍保存本次操作回执 | 第 343 行至第 375 行 |
| 新增仓库确认无权 | 整次更新失败，原范围与资料不变 | [storage.go](../../internal/projects/storage.go) 第 231 行 |
| 原范围受限时修资料或配置 | 允许；不要求对已保存受限仓库重新证明读权 | [service.go](../../internal/projects/service.go) 第 225 行 |
| 观察时间过期或连接变化 | 503 `AUTHORIZATION_UNCONFIRMED`，不写入 | [project_access.go](../../internal/access/project_access.go) 第 200 行 |
| 范围修订变化 | 旧范围游标 409 `PROJECT_CONTEXT_CHANGED` | [service.go](../../internal/projects/service.go) 第 629 行 |
| 回执正文被清理 | 410，旧键不复活 | [service.go](../../internal/projects/service.go) 第 444 行 |
| 列表游标过期 | 409 `CURSOR_EXPIRED`，从第一页重读 | [storage.go](../../internal/projects/storage.go) 第 466 行 |

测试用的事务阶段钩子（`authorization_observed`、`operation_inserted`、`project_written`、`repository_written`、`configuration_written`、`project_reference_written`、`receipt_written`、`before_commit`）只在测试进程注入，见 [types.go](../../internal/projects/types.go) 第 268 行；生产装配下始终为 nil。它们用于证明“任一写入失败不会留下半提交状态”，不是产品故障开关。

## 设计理由

同一事务保存五类事实，用户看到的“保存成功”与数据库里存在的东西一致。回执与当前快照分开，重试不会因为后续编辑而改变旧结果。

配置引用固定到不可变修订，默认或秘密版本变化只更新观察，不暗换已保存项目。仓库范围只增不删且每页重新核权，避免用一次列表刷新改写用户已保存的范围。

`canCreateIssue` 与 `creationReadiness` 保持受限，是因为 Issue 与运行尚未接入；这不是 UI 遗漏，而是对完成度的真实表达。

## 验证清单

以下为可观察的预期结果。本批已执行过一次主目录集成验证；复跑必须使用真实 PostgreSQL 与真实 HTTP，跳过集成测试不算通过。

- 创建 201、同键同输入重放 200 且回执字段不变；同键不同输入 409。
- 两个并发同键创建只产生一个项目与一个回执。
- 原操作查询只对原操作者可见；正文清理后返回 410，旧键不能用于新创建。
- 更新携带旧 `expectedProjectRevision` 返回 409；已提交操作重放优先于该判断。
- 无变化更新不增加 `projectRevision`，但仍返回成功回执。
- 新增仓库在 denied 或 unknown 时整次回滚，原范围与资料不变。
- 原范围受限时修改名称或显式配置仍成功，受限仓库名称不返回。
- 显式更新配置产生新的 `configurationRevision`；省略配置保留原版本。
- 范围修订变化后旧范围游标返回 409 `PROJECT_CONTEXT_CHANGED`。
- 列表与配置游标超过 10 分钟返回 409；跨主体或改查询复用游标返回 400。
- 未配置认证时八个端点都返回 503 `AUTH_NOT_CONFIGURED`，`/readyz` 仍为 503。
- 独立复核：无开放 P0/P1/P2，`businessReady=false`，整批业务未 `VERIFIED`。

# B05 模型测试与应用

B05 在 B04 已保存的供应商快照上做两件事。用户先对某个固定模型发起一次连通性测试，明确可能收费后登记一次请求；再把自己有权项目里的模型换成另一个固定快照，同时完整保留原有 execution 配置。项目读接口另外返回固定预算与时限摘要，以及当前额度观察。

本批产品未实现，运行未验收。设计状态分三层：B04 已实现的事实是本批输入；测试预览与 handler 观察、unknown 运维关闭、逐路径锁序与共同 owner account 边界、schema2 唯一 `executionProfiles` 集合、窗口 scope 约束五项已在 [B05/B06 设计收口](../development/2026-09-14-b05-b06-design-closeout-01/README.md) 固定为后续实现基线；D05、D06、C05、C06 以及全部候选数值仍未采用。字段唯一来源是 [模型浏览器候选](../current/model-settings-browser-api-draft.md) 与 [首批浏览器契约 C05](../current/first-batch-browser-api-contract.md)，内部事务唯一来源是 [模型内部操作候选](../current/backend-model-operations-draft.md) 第 8 节与 [来源候选](../current/backend-first-batch-sources-draft.md) 第 9 节。跨批公共规则见 [公共规则](./foundations.md)。

## 公共约定

本批字段骨架沿 B04 与 B03 的既有边界，不另建传输协议。

| 约定 | 行为 |
| --- | --- |
| 认证 | Cookie 会话；写请求要求单值 `Origin` 与 `X-CSRF-Token`；错误体与 B04 相同。 |
| 预览角色 | 预览只建立短期比较上下文，不是授权令牌，不预留额度或槽位，不发送模型请求。 |
| 固定快照 | 测试与新应用只针对当前已保存快照发起；已提交操作继续使用自己的快照，不受后续 head 变化影响。 |
| 模型秘密 | 只使用 `model-provider-key` 业务密文；比较 vault 与清理入口不向 transport 开放。 |
| 出站边界 | 固定目标与协议，禁止重定向、环境代理与自动重试；详细地址策略见 [来源候选](../current/backend-first-batch-sources-draft.md) 第 6 节。 |
| 费用语义 | 本地只记请求次数；`currency` 与金额字段始终为 null，不声称金额上限或账单结算。 |
| 运行无关 | 测试成功不是应用模型、创建 Issue 或启动运行的前置条件。 |

## 状态与枚举

对外状态由持久事实投影，内部 dispatch 子阶段不直接成为 HTTP 枚举，来源见 [模型浏览器候选](../current/model-settings-browser-api-draft.md) 第 4 节。

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `state` | `queued` | 已登记，尚无实际调用开始观察。 |
| `state` | `running` | 已观察到实际传输开始且尚未得到结果。 |
| `state` | `passed` | 该次请求取得完整、可解析、符合协议的成功响应。 |
| `state` | `failed` | 明确拒绝响应或已确认响应无效；可能已收费。 |
| `state` | `unknown` | 外部可能已发送，未能确认结果。超时、崩溃与结果落库失败都可能产生该状态。 |
| `state` | `rejected` | 已证明未进入可能发送阶段，或证明未发出且旧发送能力失效。 |
| `budget.status` | `reserved`、`consumed`、`released` | 本地 1 次请求额度；只有可证明未发送才能释放。 |
| `charge.status` | `not_sent`、`possible`、`unknown` | 费用观察，不表示金额结算。 |
| `recovery.state` | `open`、`closed_without_result`、`not_needed` | `passed`、`failed`、`rejected` 为 `not_needed`；已运维关闭的 unknown 为 `closed_without_result`，历史 `state` 仍为 `unknown`。 |
| `resultRevision` | 不透明字符串 | 只做等值比较或由服务端单调推进，客户端不比较字典序。 |

## HTTP API

以下路径与字段是待采用的机器协议，均未实现。路径以 [模型浏览器候选](../current/model-settings-browser-api-draft.md) 的 M02 接口目录为准。

### POST /api/model-test-previews

#### 调用方与授权

模型设置页。调用者必须拥有该供应商，且目标模型行属于该供应商当前已保存修订。

#### 输入

| 字段 | 类型 | 必填 | 约束 | 含义 |
| --- | --- | --- | --- | --- |
| `providerId` | string | 是 | UUID 形状 | 目标供应商。 |
| `providerRevision` | string | 是 | UUID 形状 | 目标修订，必须等于当前 head。 |
| `modelRowId` | string | 是 | UUID 形状 | 目标模型行。 |

#### 返回

`200 OK`，返回预览对象。关键字段为 `previewId`、`expiresAt`、`providerId`、`providerRevision`、`modelRowId`、`modelId`、`secretVersionId`、`policyRevision`、`cost`、`requestLimit`、`canSubmit`、`reasonCodes`。`cost` 取 `{basis:"request_count",units:1,mayCharge:true,currency:null,maxEstimatedCharge:null}`。`requestLimit.maxOutputTokens` 取 `min(16, 该模型 maxOutputTokens)`，其中 16 是候选值，未采用；`requestLimit.timeoutSeconds` 取固定时限政策版本值，不得预览一个值而实际执行另一个值。

`canSubmit` 为 false 时 `reasonCodes` 可能包含 `TEST_ALREADY_OUTSTANDING`、`QUOTA_UNAVAILABLE`、`EGRESS_NOT_ALLOWED`、`SECRET_UNAVAILABLE`、`PROFILE_UNAVAILABLE`、`TEST_HANDLER_UNAVAILABLE`、`LIMIT_UNSUPPORTED`。只有 `TEST_ALREADY_OUTSTANDING` 分支额外返回顶层 `existingTestId` 与 `links.operation`，且两者同时出现。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 404 | `RESOURCE_NOT_FOUND` | 供应商、修订或模型行不可见。 |
| 409 | 不适用 | 预览不返回业务冲突；冲突在提交阶段表达。 |
| 503 | `AUTHORIZATION_UNCONFIRMED` | 当前资格或出站资格无法确认。 |
| 503 | `TEST_HANDLER_UNCONFIRMED` | 处理器登记读取失败。该失败不创建预览记录，也不使用 `RESULT_UNCONFIRMED`。 |
| 503 | `AUTH_NOT_CONFIGURED`、`RESULT_UNCONFIRMED` | 未配置认证；数据库不可用。 |

#### 并发与重放

预览在同一次当前主体观察中分别读取三项事实：当前 actor 未核清测试、额度窗口、匹配协议的处理器登记。三者互不替代。预览不预留额度或槽位，因此预览通过不构成提交许可；提交阶段必须在事务内重查并以 409 拒绝竞争。

#### 设计理由

预览要回答“现在能不能再发一次可能收费的请求”，因此必须同时看到占用、额度与处理器。把预览当锁会让两个标签页互相阻塞；把它当纯展示又会漏掉提交竞争。实现选择展示加提交重查。

### POST /api/model-tests

#### 调用方与授权

测试表单。写请求要求 `Origin` 与 CSRF；`Idempotency-Key` 就是本次 `testId`。

#### 输入

| 字段 | 类型 | 必填 | 约束 | 含义 |
| --- | --- | --- | --- | --- |
| `previewId` | string | 是 | 未过期且属于当前 actor | 预览定位。 |
| `confirmPotentialCharge` | boolean | 是 | 必须为 true，false 返回 422 | 明确可能收费。 |

#### 返回

首次登记 `202 Accepted`，请求体为 `TestResult`。原键与原输入重放返回原回执。`TestResult` 字段为 `testId`、`providerId`、`providerRevision`、`modelRowId`、`state`、`resultRevision`、`acceptedAt`、`observedAt`、`result`、`budget`、`charge`、`recovery`、`links.operation`。`202` 只表示本地登记与持久责任，不表示测试通过。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 409 | `TEST_PREVIEW_CHANGED` | 版本或政策已经变化。 |
| 409 | `TEST_PREVIEW_EXPIRED` | 预览过期。 |
| 409 | `TEST_ALREADY_OUTSTANDING` | 当前 actor 已有 `queued`、`running` 或 `recovery.open` 的 unknown。当前 actor 仍可读阻断记录时，`error.details` 为 `{existingTestId,links:{operation}}`。 |
| 409 | `TEST_BUDGET_UNAVAILABLE` | 额度不足。 |
| 409 | `TEST_HANDLER_UNAVAILABLE` | 没有匹配协议与输出限制映射的处理器登记。 |
| 503 | `TEST_HANDLER_UNCONFIRMED` | 处理器登记读取失败，不登记测试、不预留额度、不消费预览。 |
| 422 | `VALIDATION_FAILED` | 字段非法或 `confirmPotentialCharge` 不为 true。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同键不同规范化输入。 |

#### 并发与重放

提交先按 `(actor,testId)` 读原操作，命中且输入一致时直接返回原回执，优先于预览期限、处理器、未核清测试、额度与其他新建检查。没有原操作时，短事务重查全部条件后登记 `queued`、预留 1 单位额度、写唯一测试工作与接受事实，并把预览消费绑定到该 `testId`。同一预览只能有一个 `testId` 消费。锁序为 `binding → session → account → operation → catalog/profile → Provider → Preview → testBinding/政策 → BudgetWindow → actor 未核计数 → secret availability`。

#### 设计理由

先登记再发送，崩溃时留下可核查责任，不会静默丢失一次可能收费的请求。原键重放优先于新条件，避免用户刷新页面后既拿不到原结果又多发一次请求。

### GET /api/model-tests/{testId}

#### 调用方与授权

结果页与恢复页。只查询当前 actor 自己的测试；不触发新的模型请求。

#### 输入

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 路径 `testId` | UUID 形状字符串 | 是 | 原操作键。 |

#### 返回

与登记响应同形的 `TestResult`，`state`、`observedAt` 与 `result` 随持久事实推进。`result` 非 null 时包含 `code`、`summary`、`latencyMs` 与 `usage`。`usage` 只来自可核实响应，缺失为 null。不保存供应商原始响应正文。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 404 | `MODEL_TEST_NOT_FOUND` | 当前 actor 无该键记录。这不证明操作未发生。 |
| 410 | `MODEL_TEST_RESULT_REMOVED` | 展示正文已清理；不触发新探测。 |
| 401、503 | `AUTHENTICATION_REQUIRED`、`RESULT_UNCONFIRMED` | 会话失效；数据库不可用。 |

#### 并发与重放

轮询建议间隔 2、5、10、30 秒（候选值，未采用），隐藏页面时暂停，单请求合并。一次客户端查询在途时，其后回读覆盖旧结果；按 actor、目标与请求代次丢弃晚到响应。`resultRevision` 只作等值比较。

#### 设计理由

查询是只读动作，用户核查未知状态时不会因为轮询本身增加外发次数。旧响应丢弃规则避免切换标签页后把旧测试结果画到新目标上。

### POST /api/projects/{projectId}/model-application-previews

#### 调用方与授权

项目模型替换弹窗。调用者必须是项目 owner 且具备配置资格。

#### 输入

| 字段 | 类型 | 必填 | 约束 | 含义 |
| --- | --- | --- | --- | --- |
| `providerId` | string | 是 | UUID 形状 | 候选供应商。 |
| `providerRevision` | string | 是 | UUID 形状 | 候选修订。 |
| `modelRowId` | string | 是 | UUID 形状 | 候选模型行。 |

#### 返回

`200 OK`，返回应用预览。字段为 `previewId`、`expiresAt`、`projectId`、`expectedProjectRevision`、`before`、`candidate`、`canApply`、`reasonCodes`。`before.model` 用三分支联合，不用裸 null。

| 分支 | 字段 |
| --- | --- |
| 未配置 | `{status:"unconfigured"}`。 |
| 可读 | `{status:"readable",reference:ProfileChoice,modelProfileId,modelProfileVersion,providerId,providerRevision,modelRowId,links:{snapshot}}`。 |
| 受限 | `{status:"restricted",reasonCodes:["ORIGINAL_MODEL_UNAVAILABLE"]}`，不返回名称、地址、profile、provider 或行 ID。 |

`before.execution` 保留原引用与有效版本；原有效版本无法确认时 `canApply=false` 且 `reasonCodes` 含 `EXECUTION_SNAPSHOT_UNCONFIRMED`。已知固定历史版本当前不可用时允许受限保存并给出对应 reason。原模型受限不阻止有权的配置修复。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 404 | `RESOURCE_NOT_FOUND` | 项目不可见或候选不可读。 |
| 503 | `AUTHORIZATION_UNCONFIRMED` | 当前资格未知。 |
| 503 | `RESULT_UNCONFIRMED` | 数据库或秘密可用性读取失败。 |

#### 并发与重放

预览是短期记录，绑定 actor、项目、项目修订、配置修订、原模型、原 execution 完整引用与候选固定版本。它不是授权令牌，也不消费任何东西。预览期间的 Provider head 变化会让提交返回冲突并要求重新预览。

#### 设计理由

应用只换模型，却必须证明 execution 被完整保留。把原 execution 的完整引用与有效版本放进预览，提交时逐项比较，才能避免“看起来没变、实际换成新默认”的漂移。

### POST /api/projects/{projectId}/model-applications

#### 调用方与授权

与应用预览同源。写请求要求 `Origin` 与 CSRF；`Idempotency-Key` 是本次 `applicationId`。

#### 输入

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `previewId` | string | 是 | 未过期且属于当前 actor 与该项目的预览。 |

#### 返回

成功 `200 OK`，返回 `{applicationId,outcome:"committed",projectId,projectRevision,configurationRevision,providerRevision,modelProfileId,retainedExecutionVersionId,committedAt,links:{project,operation}}`。`retainedExecutionVersionId` 必须与预览一致。确定拒绝返回持久拒绝回执，主键字段改为 `applicationId`。没有实际变化时保留原配置与项目修订，仍然写入本操作回执并消费预览。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 409 | `MODEL_APPLICATION_PREVIEW_CHANGED` | 候选或项目比较基线变化。 |
| 409 | `PROJECT_REVISION_CONFLICT` | 项目在预览后变化。 |
| 409 | `EXECUTION_SNAPSHOT_UNCONFIRMED` | 原 execution 有效版本无法确认。 |
| 409 | `PREVIEW_ALREADY_CONSUMED` | 同一预览已被其他操作消费。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同键不同输入。 |
| 410 | `MODEL_APPLICATION_RESULT_REMOVED` | 原记录已清理。 |
| 503 | `RESULT_UNCONFIRMED` | 提交结果未知。 |

#### 并发与重放

提交先重放原 `applicationId`，再检查预览、项目与配置修订、候选固定版本、原 execution 引用与有效版本。锁序为 `binding → session → account → project → operation → catalog/profile → Provider → Preview → secret availability`，与 B03 项目写共用 `project` 前缀。冲突整笔不写配置。

#### 设计理由

项目模型与 execution 必须一起固定。若应用走完整配置 PATCH，就会重新解析 execution 默认并可能换掉用户的运行配置。专用应用把改动面收窄到模型引用，其他固定参数逐项复制。

与提交同形的已提交或已拒绝回执。重放不代表项目当前仍是该版本，当前配置要另读项目接口。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |

### GET /api/projects/{projectId} 的 C05 只读字段

#### 调用方与授权

项目页复用现有项目读取。新增两个字段，不新增策略查询端点，字段唯一来源是 [首批浏览器契约 C05](../current/first-batch-browser-api-contract.md) 第 10 节。

#### 返回

`configuration` 内新增 `fixedSummary` 与 `quotaObservation`。

| 字段 | 形状 |
| --- | --- |
| `fixedSummary.configurationRevision` | string。 |
| `fixedSummary.executionVersionId` | string 或 null。 |
| `fixedSummary.budget` | `{status:"available",policyId,policyVersion,scope:"project_model_runtime",unit:"request",period:"utc_day",limit,maxUnresolved}` 或 `{status:"unresolved",reasonCodes}`。 |
| `fixedSummary.timeLimits` | `{status:"available",policyId,policyVersion,modelRequestTimeoutSeconds,workerAttemptLimitSeconds}` 或 `{status:"unresolved",reasonCodes}`。 |
| `quotaObservation` | `known`、`unknown`、`not_configured` 三分支，`known` 含窗口起止、`effectiveLimit`、`reserved`、`consumed`、`remaining`、`observedAt`。 |

`available` 表示原固定参数可读，不表示当前启用、额度充足或进程停止。`unresolved` 不填 0 或推荐默认值。`not_configured` 只用于原固定配置没有可解析运行预算。`unknown` 表示没有可靠账本或读取失败，不伪造 0。

#### 错误与状态码

可选额度观察失败时返回 `quotaObservation.unknown`；项目主体或配置快照整体不可读时整次返回 503 `AUTHORIZATION_UNCONFIRMED`，不拼旧快照。

#### 并发与重放

固定摘要与 `effective` 来自同一配置版本；额度允许稍后变化。只读 GET 不创建窗口、不消费额度、不重解析默认、不跟随新默认。

#### 设计理由

用户需要在项目页看到“当时的预算与时限是多少”以及“今天还剩多少”，但两者来源不同。把固定历史与当前额度分开，就不会因为后来政策变化而篡改历史配置的展示。

## 协调进程内部边界

测试外发只由 coordinator 的 `TestRunner` 负责，Web 不持有出站调用对象。相关声明见 [b05.go.txt](../development/2026-09-13-b04-b06-design-01/b05.go.txt)。

### 一次发送许可

每个 `testId` 只能从未发阶段原子生成一次随机 `sendPermit` 与 `externalOperationId`，在同一事务里持久 `may_have_sent` 并把额度从 `reserved` 转为 `consumed`。只有收到本次事务明确 COMMIT 回执、且持有内存一次性许可的进程可以进入 transport。许可事务 COMMIT 回执丢失时，即使随后从数据库读到许可记录，也进入 `unknown`，不重新取得或恢复发送能力。重启只重新领取尚未有许可的 `queued` 记录，存在许可的一律核查。

### 处理器登记

有限 `test_handler_leases` 记录 coordinator 实例的随机不可复用 `instanceId`、确切 `protocolVersion` 与租约。候选参数为 60 秒租约、20 秒续期。Web 预览与新提交只读取未过期且支持该目标输出限制的登记。没有记录为 `TEST_HANDLER_UNAVAILABLE`；读取失败为 503 `TEST_HANDLER_UNCONFIRMED`。租约过期不是撤销证明，不能自动关闭 unknown 或重新授予许可。

### repomesh-coordinator model-tests unknown inspect

只读检查命令，路径为 `model-tests unknown inspect --actor-id <ID> --test-id <UUID>`。它返回 actor、测试、外部操作、发送许可、发送实例、凭据能力引用、状态、recovery、budget 与既有关闭回执，不读取原始 Secret、响应正文或许可 nonce。

### repomesh-coordinator model-tests unknown close

关闭命令，路径为 `model-tests unknown close --actor-id <ID> --test-id <UUID> --close-key <UUID> --evidence <PATH>`。

| 项目 | 语义 |
| --- | --- |
| 操作员身份 | 来自受控执行环境与专用数据库管理凭据。coordinator 用实际 DB `session_user`、固定部署身份与 `repomesh_model_test_maintainer` 角色生成不透明主体，每个事务重新核对；命令正文不能自报操作员。 |
| 证据 | schema 1 严格包含 actor、测试、外部操作、发送许可、发送实例、凭据能力 id 与 version，以及两类材料：准确发送实例退出材料的受控引用与 SHA-256，旧发送能力撤销材料的受控引用、SHA-256 与核查时间。 |
| 两类证据缺一不可 | 租约到期、请求超时、单次 PID 查询无结果、进程重启与 coordinator 重启都不能单独满足关闭条件。 |
| 校验 | 逐项比较证据与持久 test、dispatch、permit、sender 实例及凭据能力身份和版本；拒绝缺项、摘要非法、错绑、重用 `senderInstanceId`、权限不足或状态不是 `recovery.open` 的 unknown。 |
| 事务结果 | 保持 `state=unknown` 与额度已消费，设置 `recovery=closed_without_result`，原子清除该 actor 与该 test 的 outstanding，并追加含全部绑定、证据摘要、操作员主体与 `closedAt` 的白名单审计。 |
| 重放 | 以 `(deploymentIdentity, closeKey)` 保存原操作；同键同输入返回原回执，同键异输入冲突。COMMIT 未知时用原键恢复。 |
| 迟到结果 | 只能作为同一 `externalOperationId` 的追加观察保存，不改变 unknown、关闭事实、额度或审计，也不创建另一次发送。 |
| 不做什么 | 不退款、不释放旧许可、不重发、不伪造成 `failed` 或 `passed`；本地撤销不表示供应商远端凭据已撤销。 |

关闭命令只解除本地新测试阻塞。系统同时记录该能力引用的本地 `revokedAt` 与证据摘要，并禁止该 sender 与 permit 再取得凭据。它不冻结任何提供商的凭据查询、撤销或结果查询协议。

## 数据表

以下表名与列是候选物理设计，来自 [迁移设计附件](../development/2026-09-13-b04-b06-design-01/migration-design.md) 的 B05 一节，全部未实现。本节沿用该附件的逻辑 schema 名 `models` 与 `modelbudget`。它们是这份候选设计的逻辑名，不是现有物理 schema，也不表示 `repomesh_*` 里已有同名对象。同一附件用 `models.providers` 等逻辑名描述 B04，落地为已实现的 `repomesh_models`；B05 的实施迁移同样要写明逻辑名到物理 schema 的映射，可以并入现有 schema，也可以按现有命名规则另立。映射确定前本章不冻结物理名，表与约束语义不受影响。实际迁移在实施时另编号，并沿用现存表的精确约束名。

| `start_utc` | timestamptz | 是 | 必须等于该时刻 UTC 日 00:00 | 窗口起点。 |
| `end_utc` | timestamptz | 是 | 等于 `start_utc + 1 day` | 窗口终点。 |

### 表关系与保留

关系链为 `tests → test_dispatch → test_observations` 与 `tests → unknown_test_closures`，额度侧为 `test_reservations → windows`，预览消费由 `previews.consumed_by` 指向测试或应用操作，应用侧为 `application_operations → 项目配置修订`。

新增对象是候选的 `modelbudget` 与 `models` 表，以及 schema 2 的政策对象与执行版本扩展。复用对象是 B04 的 `repomesh_models` 与 `repomesh_secrets`、B03 的 `repomesh_projects`、schema 1 的导入表。

测试结果展示正文候选保留 30 天，清理由追加 removed 表达；`testId`、固定版本、permit、未核责任与预算消费保留。unknown 不因清理消失。预览保留最小消费墓碑。应用只清输入与回执正文，项目与固定配置修订不销毁。责任扫描与分页索引在实施时按实际查询计划补充，本文件不冻结索引清单。

## 事务与恢复

### 测试登记

1. 认证并解析 `previewId` 与收费确认。
2. 按当前主体读原 `testId`；命中且输入一致直接返回，优先于其他新建检查。
3. 无原操作时，短事务重查预览、当前 head、政策、处理器登记、未核清测试与额度。
4. 同事务写接受事实、`queued` 测试、1 单位预留、唯一测试工作、预览消费与审计。
5. 返回 202；返回丢失时用原 `testId` 查询，不再次预留。

### 发送许可与观察

1. Runner 领取尚未有许可的 `queued` 记录，不持业务锁跨网络。
2. 发送前按 account 起始顺序核 actor、固定秘密、出站、政策与旧许可。
3. 事务内原子生成许可与外部操作身份，持久 `may_have_sent` 并消费额度。
4. 只有确认 COMMIT 的进程取得内存许可并发送一次。
5. 传输开始写入 `running` 观察；完成或错误写白名单观察与正式状态。

### 应用提交

事务先重放原操作，再比较预览、项目与配置修订、候选固定版本、原 execution 完整引用与有效版本，然后只替换模型引用，保留 execution 逐项复制。没有变化时保留原修订并写稳定回执。

### 恢复场景

| 场景 | 预期结果 |
| --- | --- |
| 预览过期或政策变化 | 新提交 409 且不预留；原接受操作先重放。 |
| 同 actor 多键竞争 | 事务内最多一条未核清责任；其他请求 409，当前 actor 仍可读时给出本人定位。 |
| 许可提交前崩溃 | 未许可记录可重新处理，不产生外发。 |
| 许可 COMMIT 回执丢失或确认后发送前崩溃 | 保守进入 unknown，端点最多收到零或一次请求，数据库读取不能恢复发送许可。 |
| 发出请求后丢响应 | 原 `externalOperationId` 稳定，`unknown` 不退款、不自动新请求。 |
| UTC 换日 | 原窗口消费保留，不重置计数；跨日不清 actor 未核责任。 |
| 运维关闭缺一类证据 | 保持 `recovery=open`，预算保持 consumed。 |
| 关闭后迟到结果 | 只追加同一外部操作的观察，不改变 unknown、关闭事实与额度。 |
| execution 默认更新 | 应用复制原有效版本与参数，不重新解析默认。 |
| 原 execution 已知但当前不可用 | 允许受限保存，仍完整保留 execution，不声称可运行。 |
| 预览过期时重放既有成功 | 原回执优先，不再执行预览校验。 |
| 原记录清理 | 有权 410，旧键不复用。 |

## 设计理由

测试与应用的共同风险是“用户以为没发生，系统已经发生”。测试登记落在本地数据库，发送许可只存在于确认过提交的进程内存中，因此重启与查询都不会凭空多出一次模型请求。运维关闭要求两类带外证据，是因为租约、超时和进程重启都不能证明远端已经停止。

只换模型的应用保护的是 execution 的既有固定版本。用户调整模型时，不应该顺带改变并发、预算、时限或模板引用。固定摘要与额度观察分开展示，避免把“当初配置了什么”和“现在还能用多少”混成一个数字。

## 验证清单

以下是可观察行为的预期结果，不是已运行测试。完整映射见 [设计验收映射](../development/2026-09-13-b04-b06-design-01/ACCEPTANCE.md) 的 B05 部分与 [收口记录](../development/2026-09-14-b05-b06-design-closeout-01/README.md)，T10 到 T14 只登记待执行。

| 检查 | 预期观察 |
| --- | --- |
| 预览占用 | 额度有余量但存在未核清测试时，预览返回 `canSubmit=false`、`TEST_ALREADY_OUTSTANDING` 与本人可读定位；额度状态独立返回。 |
| 预览竞争 | 预览之后提交时条件变化，提交仍返回 409，不登记也不发送。 |
| handler 观察 | 没有登记时预览阻止提交；读取失败时 503 `TEST_HANDLER_UNCONFIRMED` 且无新记录；原键重放优先于这些检查。 |
| 许可原子性 | 许可事务回执丢失后不会出现第二次发送；重启只处理无许可记录。 |
| 未知关闭 | 缺任一材料保持 open；两类齐全时 state 仍 unknown、预算 consumed、outstanding 清除、审计写入。 |
| 额度账本 | 同 scope 同 UTC 日只能有一行窗口；降低上限只阻止新增；新日不清未核责任。 |
| schema 2 导入 | schema 1 回执不被升级；schema 2 只接受一个 `executionProfiles`；重复集合、同键跨 schema 与伪造 scope 均拒绝。 |
| 应用保留 execution | 应用后固定 JSON 中 execution 选择、版本与参数完全等于原项目；默认变化不影响结果。 |
| no-op 应用 | 引用与版本完全相同时保留原修订，仍写回执并消费预览。 |
| inherit 转 reference | 即使有效模型相同，选择依据变化产生一个新配置修订。 |
| C05 分支 | 固定摘要与 `effective` 同版本；无可信窗口给 unknown 而不是 0；GET 不写表。 |
| C06 分支 | 未配置、可读、受限三分支精确；受限不泄露 ID；只读可读分支取指定快照。 |

# B04 模型供应商保存与执行来源导入（已有实现；本地集成验证，非整批 VERIFIED）

B04 是首批模型配置的来源批次。用户在当前账号下保存一个自己的模型供应商完整快照，再按原 `saveId` 查询这次保存；结果未知时可以明确终结原槽位，让同一键以后不能保存。部署人员用受限命令行登记执行模板、执行版本和显式固定默认，浏览器不提供导入入口。

本批已合入 `main`，状态为 `INTEGRATED_LOCAL_VERIFIED`，授权范围已经结束，不等于整批业务 `VERIFIED`。采用范围与限制见 [B04 采用记录](../current/b04-model-sources-adoption.md)，运行证据见 [B04 验收报告](../development/2026-09-13-b04-acceptance-01/README.md)。跨批公共规则（身份作用域、事务与重放、版本与执行边界）见 [公共规则](./foundations.md)；错误体形状见本章「公共约定」的错误体行。

## 公共约定

六个模型端点都走 `registerModels` 装配，见 [models.go](../../internal/web/models.go) 第 21 行。每个端点共用以下边界。

| 约定 | 行为 |
| --- | --- |
| 认证 | Cookie 会话必须有效。`POST` 额外要求单值 `X-CSRF-Token` 与单值 `Origin` 等于部署 origin，见 [models.go](../../internal/web/models.go) 第 98 行的 `registerModelRoute`。 |
| 未配置认证 | 正常进程组装下模型服务为零值，业务路由不注册，`/api/*` 落到通用 404，见 [server.go](../../internal/web/server.go) 第 113 行。`registerModelRoute` 仍为「服务存在但认证缺失」的组合保留 503 `AUTH_NOT_CONFIGURED`。 |
| 请求超时 | 每个请求 15 秒上下文超时，超时后按 503 `RESULT_UNCONFIRMED` 处理。 |
| 响应头 | 统一 `Cache-Control: no-store` 与 `Referrer-Policy: no-referrer`。 |
| 错误体 | `{"error":{"code","message","fieldErrors","requestId"}}`，由 [projects.go](../../internal/web/projects.go) 第 206 行的 `writeProjectError` 生成；模型错误经 [models.go](../../internal/web/models.go) 第 156 行转换。 |
| 请求体 | `Content-Type` 只接受 `application/json`（可带 `charset=utf-8`）；保存体上限 256 KiB，close 体上限 256 字节。 |
| 幂等键 | `Idempotency-Key` 必须出现且只能一个值，UUID 形状；保存键是 `saveId`，close 键必须等于路径 `saveId`。 |
| 账号隔离 | 所有读写以当前认证 actor 为 owner；不存在的资源与他人资源同样按 404 处理。 |
| 授权锁 | 每个端点先锁主体绑定、会话与账号，再进入各自业务锁；逐路径锁序见下文与 [公共规则](./foundations.md)。 |

## HTTP API

### GET /api/model-providers

#### 调用方与授权

模型设置页供应商列表。调用者必须是当前认证 actor；只返回 `owner = actor` 的供应商，其他 owner 的行不可见。

#### 输入

| 参数 | 类型 | 必填 | 约束 | 含义 |
| --- | --- | --- | --- | --- |
| `q` | string | 否 | 有效 UTF-8，最多 200 个 Unicode 标量 | 供应商名称字面子串，大小写不敏感。 |
| `cursor` | string | 否 | 最多 128 字符，且为服务端先前返回的值 | 继续位置。 |
| `limit` | integer | 否 | 1 到 100，默认 50 | 单页条数。 |

解析见 [input.go](../../internal/models/input.go) 第 53 行 `ParseListQuery`。

#### 返回

`200 OK`，形状为 `{items:[{id,name,revision,modelCount}],nextCursor}`。`items` 恒为数组，`modelCount` 是该供应商当前 head 版本的模型行数，`nextCursor` 只在还有下一页时非 null。排序按 `provider id` 升序，没有 `total` 字段。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 400 | `INVALID_CURSOR` | 游标不存在，或游标属于其他 actor、其他 `q`、其他 `limit`。 |
| 409 | `CURSOR_EXPIRED` | 游标超过 10 分钟有效期。 |
| 422 | `VALIDATION_FAILED` | `q` 或 `limit` 非法。 |
| 401 | `AUTHENTICATION_REQUIRED` | 会话或绑定失效。 |
| 503 | `AUTH_NOT_CONFIGURED`、`RESULT_UNCONFIRMED` | 未配置认证；数据库或锁不可用。 |

#### 并发与重放

分页游标写入 `repomesh_projects.cursors`，`kind` 固定为 `providers`，绑定 actor、`q` 与 `limit`。实现只在需要下一页时写新游标行，见 [service.go](../../internal/models/service.go) 第 16 行。翻页期间新增的供应商可能出现在后续页，本接口不承诺跨页快照一致；游标失效时应从首屏重读，不拼接旧页。

#### 设计理由

游标绑定主体和查询条件，避免把其他账号的翻页位置当成授权。查询失败返回 503 而不是空列表，用户不会因为一次数据库抖动看到“没有供应商”的错误结论。

### GET /api/model-providers/{id}

#### 调用方与授权

模型设置页供应商详情与保存后的回读。只允许当前 actor 读取自己拥有的供应商。

#### 输入

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 路径 `id` | UUID 形状字符串 | 是 | 供应商 ID。非 UUID 直接按 404 处理。 |

#### 返回

`200 OK`，返回当前 `head_revision` 的完整快照。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | string | 供应商稳定身份。 |
| `name` | string | 该修订的名称，1 到 100 字符。 |
| `revision` | string | 不可变快照版本，UUID 形状。 |
| `baseUrl` | string | 规范化 HTTPS 基础地址。 |
| `apiFormat` | string | 首批固定 `openai_chat_completions`。 |
| `secret.configured` | boolean | 是否绑定密文版本。当前实现恒为 true，因为每个修订都要求 `secret_version_id` 非空。 |
| `secret.versionId` | string | 该修订绑定的密文版本身份，不回显明文。 |
| `secret.availability` | string | `available`、`unavailable`、`unknown`、`missing` 四值之一，含义见下。 |
| `models[].id` | string | 稳定模型行 ID。 |
| `models[].modelProfileId` | string | 稳定模型配置 ID，应用时固定使用。 |
| `models[].modelId` | string | 外部模型名，1 到 200 字符。 |
| `models[].displayName` | string | 显示名；输入省略或为空时取 `modelId`。 |
| `models[].contextWindow` | integer | 上下文窗口，1 到 2147483647。 |
| `models[].maxOutputTokens` | integer | 最大输出，1 到 `contextWindow`。 |
| `models[].reasoning`、`models[].vision` | boolean | 能力布尔值，不从模型名推断。 |
| `updatedAt` | RFC3339 | 该修订创建时间。 |

`availability` 由秘密可用性观察投影，见 [storage.go](../../internal/models/storage.go) 第 197 行 `readProvider`。`available` 表示密文与包装根都可读，`unavailable` 表示已销毁或停用，`unknown` 表示当前包装根不可用，`missing` 表示可用性元数据不存在。任何一种都只说明受控存储状态，不证明远端供应商接受该 Key。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 404 | `RESOURCE_NOT_FOUND` | 非 UUID、非本 owner、行不存在，或该修订的模型快照集合为空。 |
| 401 | `AUTHENTICATION_REQUIRED` | 会话失效。 |
| 503 | `RESULT_UNCONFIRMED` | 数据库或秘密可用性读取失败。 |

#### 并发与重放

读取在可写事务中锁主体后读取 head，不修改任何业务行。保存与此读取并发时，读取看到锁前或锁后的完整快照之一，不返回半套模型行。

#### 设计理由

详情只暴露能力观察，不暴露 Key 明文或尾号。密文状态与远端可用性分开，用户看到 `available` 时也不会误以为模型一定可调用。

### GET /api/model-providers/{id}/versions/{revision}

#### 调用方与授权

历史固定来源展示。任何有权读取该供应商的当前 actor 都可以读取任意已保存修订，用于核对旧项目或旧预览引用的确切快照。

#### 输入

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 路径 `id` | UUID 形状字符串 | 是 | 供应商 ID。 |
| 路径 `revision` | UUID 形状字符串 | 是 | 不可变修订 ID。 |

两个参数任一不合法都按 404 处理，见 [service.go](../../internal/models/service.go) 第 87 行 `GetVersion`。

#### 返回

与详情同形的完整快照，但 `revision` 固定为请求版本。修订行与模型快照都不可更新，读取结果不随新保存变化。

#### 错误与状态码

与详情一致。历史修订存在但模型行缺失时返回 503 `RESULT_UNCONFIRMED`，不返回空模型数组。

#### 并发与重放

幂等只读。并发的新保存只影响新修订，不改变本接口结果。

#### 设计理由

没有固定版本读取，页面只能用最新版本展示历史引用，会把旧项目参数显示成新参数。该端点让“当时的版本”可被核对，且不要求重新查询列表推断来源。

### POST /api/model-provider-saves

#### 调用方与授权

模型 Key 保存页。写请求必须带单值 `Origin` 与 `X-CSRF-Token`，`Idempotency-Key` 就是本次 `saveId`。

#### 输入

| 字段 | 类型 | 必填 | 约束 | 含义 |
| --- | --- | --- | --- | --- |
| `providerId` | string 或 null | 是 | UUID 形状；必须与 `expectedRevision` 同时出现或同时省略 | 更新目标。新建时为 null。 |
| `expectedRevision` | string 或 null | 是 | UUID 形状 | 更新比较基线，防止覆盖他人并发保存。 |
| `name` | string | 是 | 1 到 100 字符 | 供应商显示名。 |
| `baseUrl` | string | 是 | 最多 2048 字符；仅 HTTPS；无 userinfo、query、fragment；去尾斜杠；不得以 `/chat/completions` 结尾 | 基础地址。 |
| `apiFormat` | string | 是 | 首批只接受 `openai_chat_completions` | 协议格式。 |
| `secret.mode` | string | 是 | `keep` 或 `replace` | Key 意图。 |
| `secret.value` | string | 仅 `replace` | 1 到 8192 字节，原样使用，不 trim | 只写值，不回显。 |
| `models` | array | 是 | 1 到 50 项 | 该修订的完整模型集合。 |
| `models[].id` | string 或 null | 否 | 已存在行的稳定 ID | 更新时必须属于该供应商。 |
| `models[].modelId` | string | 是 | 1 到 200 字符，且同一请求内唯一 | 外部模型名。 |
| `models[].displayName` | string 或 null | 否 | 最多 200 字符 | 显示名。 |
| `models[].contextWindow` | integer | 是 | 1 到 2147483647 | 上下文窗口。 |
| `models[].maxOutputTokens` | integer | 是 | 1 到 `contextWindow` | 最大输出。 |
| `models[].reasoning`、`models[].vision` | boolean | 是 | 无 | 能力声明。 |

解析规则见 [input.go](../../internal/models/input.go) 第 68 行 `parseSave`、第 155 行 `parseSecret`、第 187 行 `parseModels`、第 241 行 `parseBaseURL`。未知字段返回 422 并指出字段名；新建省略 `secret` 或使用 `keep` 返回 422 `secret:REQUIRED`。更新时已有模型行不能省略，也不能引用其他供应商的行，见 [storage.go](../../internal/models/storage.go) 第 247 行。

#### 返回

新建成功 `201 Created`，更新成功 `200 OK`，已提交重放 `200 OK`。

```json
{
  "saveId": "a2394178-23a4-43ba-a886-2755c1f9ad16",
  "outcome": "committed",
  "providerId": "0f0b0d16-6f6e-4d5a-9a2c-0f1f8b1f2a01",
  "providerRevision": "5c9f2b8e-1a2b-4c3d-8e4f-5a6b7c8d9e0f",
  "secretVersionId": "7f1e2d3c-4b5a-4697-8899-aabbccddeeff",
  "committedAt": "2026-09-11T12:01:00Z",
  "links": {
    "provider": "/api/model-providers/0f0b0d16-6f6e-4d5a-9a2c-0f1f8b1f2a01",
    "operation": "/api/model-provider-saves/a2394178-23a4-43ba-a886-2755c1f9ad16"
  }
}
```

已持久确定的修订冲突返回 `409`，正文是拒绝回执，形状为 `{saveId,outcome:"rejected",error:{code,message,fieldErrors,requestId},decidedAt}`。当前实现只对 `PROVIDER_REVISION_CONFLICT` 写这种回执，见 [service.go](../../internal/models/service.go) 第 187 行 `commitSave`。

原子终结后的同键保存返回 `409 MODEL_SAVE_CLOSED`，优先级高于输入比较与新修订校验。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 400 | `INVALID_JSON`、`INVALID_IDEMPOTENCY_KEY` | JSON 格式或重复属性非法；`Idempotency-Key` 缺失、多值或非 UUID。 |
| 403 | `ORIGIN_REJECTED` | 写请求的 `Origin` 缺失、多值或不等于部署 origin。 |
| 409 | `PROVIDER_REVISION_CONFLICT` | 更新时当前 head 不等于 `expectedRevision`。回执已持久，回读后可重新发起新操作。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同键再次提交的规范化输入不同。 |
| 409 | `MODEL_SAVE_CLOSED` | 该键已经被原子终结。 |
| 410 | `MODEL_SAVE_RESULT_REMOVED` | 该键的正文已被维护入口清理。 |
| 413 | `REQUEST_TOO_LARGE` | 请求体超过 256 KiB。 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | `Content-Type` 不是 `application/json`。 |
| 422 | `VALIDATION_FAILED` | 字段非法、未知字段、模型集合不含全部既有行。 |
| 503 | `RESULT_UNCONFIRMED`、`AUTH_NOT_CONFIGURED` | 提交结果未知、秘密包装次数耗尽、数据库或锁不可用。 |

#### 并发与重放

保存先按主体与键查原操作。存在 `committed`、`rejected` 或 `closed_without_save` 时直接重放或按对应规则拒绝，不再做新修订校验。新操作在短事务内按 `binding → session → account → operation slot → catalog → Provider` 取锁，提交路径见 [service.go](../../internal/models/service.go) 第 187 行；目录与 Provider 的先后在 [service.go](../../internal/models/service.go) 第 212 行的注释中说明。

密码学材料在业务锁外预先准备，进入调用方事务后插入，见 [service.go](../../internal/models/service.go) 第 116 行 `Save` 与第 157 行 `prepareSave`。预扣包装次数不退款，进程崩溃只会浪费一次包装额度，不会留下半个可用配置。

同键不同输入的比较分两路。`replace` 保存解密独立 `operation-input` vault 后做字节比较；`keep` 保存比较非秘密规范化输入。业务 Key 之后被停用不影响旧请求比较，见 [service.go](../../internal/models/service.go) 第 424 行 `compareInput`。

#### 设计理由

用户双击保存或网络抖动重试时，只会得到一个供应商修订。Key 明文只在本次请求内存中存在，服务端保存密文和精确比较材料，不保存可离线猜测的裸哈希。修订冲突被持久成拒绝事实，用户能区分“这次确定没保存”和“结果未知”。

### GET /api/model-provider-saves/{saveId}

#### 调用方与授权

保存结果未知时的原操作查询。只查询当前 actor 自己的槽位。

#### 输入

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 路径 `saveId` | UUID 形状字符串 | 是 | 原保存操作 ID；非 UUID 按 404 处理。 |

#### 返回

`200 OK`，返回三类回执之一。`committed` 与 `rejected` 形状同保存接口，`closed_without_save` 形状为 `{saveId,outcome,closedAt,links:{operation}}`。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 404 | `MODEL_SAVE_NOT_FOUND` | 当前 actor 在该键下没有记录，或键形状非法。这不证明旧请求将来不会提交。 |
| 410 | `MODEL_SAVE_RESULT_REMOVED` | 记录已清理，键不复用。 |
| 401、503 | `AUTHENTICATION_REQUIRED`、`RESULT_UNCONFIRMED` | 会话失效；数据库不可用。 |

#### 并发与重放

查询本身不写槽位、不分配新键，见 [service.go](../../internal/models/service.go) 第 463 行 `GetSave`。同一键反复查询返回值稳定；提交方尚未完成时先返回 404，用户应继续用同一键核查。

#### 设计理由

查询不会因为一次 404 把未知状态改写成“未提交”。槽位由唯一键和主体锁保护，旧键在整个保留期内不可复用。

### POST /api/model-provider-saves/{saveId}/close

#### 调用方与授权

保存结果未知且用户明确选择终结原操作时使用。写请求要求 `Origin` 与 CSRF。路径 `saveId` 与 `Idempotency-Key` 必须一致，正文必须是空对象 `{}`，见 [input.go](../../internal/models/input.go) 第 40 行 `NewCloseCommand`。

#### 输入

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| 路径 `saveId` | UUID 形状字符串 | 是 | 与原保存同一键。 |
| 请求头 `Idempotency-Key` | UUID 形状字符串 | 是 | 必须等于路径值。 |
| 请求体 | JSON 对象 | 是 | 解析后必须严格等于 `{}`，最多 256 字节。 |

不接受 `providerId`、原修订、配置正文、Key、摘要或“用户确认未保存”之类的自报字段。

#### 返回

`200 OK`，按槽位当前事实返回 `committed`、`rejected` 或 `closed_without_save` 之一。已经提交的保存不会被撤销，已拒绝的保存不会改写 `decidedAt`。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 400 | `INVALID_IDEMPOTENCY_KEY`、`INVALID_JSON` | 路径与头不一致；正文不是 `{}`。 |
| 409 | 不适用 | close 自身不返回业务 409；竞争结果由槽位事实决定。 |
| 410 | `MODEL_SAVE_RESULT_REMOVED` | 原记录已清理。 |
| 503 | `RESULT_UNCONFIRMED` | 另一事务持槽、锁等待耗尽或提交结果未知。 |

#### 并发与重放

close 与原保存竞争同一个唯一槽位，见 [service.go](../../internal/models/service.go) 第 496 行 `CloseSave`。原保存先提交时 close 返回原 `committed`；close 先提交时空槽位写入 `closed_without_save`，此后同键保存返回 `MODEL_SAVE_CLOSED`。重复 close 返回同一 `closedAt`，不分配第二个操作键。

#### 设计理由

“终结”只终结指定键，不撤销已经保存的配置，也不影响其他键。用户不必重新输入 Key 就能解除未知状态，而旧输入相同与否都不会让已终结的键重新执行。

### 模型恢复页面路由

`GET /settings/model-saves/{id}` 返回前端入口页。该路由只接受 36 字符、无百分号编码的 UUID，供丢响应后回到原操作页面，见 [models.go](../../internal/web/models.go) 第 169 行 `modelBrowserRoute`。浏览器恢复键 `repomesh.model.save-index.v1`（localStorage 最小索引）与 `repomesh.model.save.v1:{actor}:{id}`（sessionStorage 非秘密快照）保持 B04 现状，见 [modelRecovery.ts](../../web/src/modelRecovery.ts) 第 15 到 16 行。

| --- | --- |
| 0 | 导入提交或原键重放成功。 |
| 2 | 用法错误、清单校验失败、`DEPLOYMENT_FORBIDDEN`、`IMPORT_NOT_FOUND`、`UNKNOWN_OWNER`、`IMPORT_CONFLICT`、`TEMPLATE_CONFLICT`、`EXECUTION_CONFLICT`。 |

## 事务与恢复

### 保存正常路径

1. 解析信封、认证、核 `Idempotency-Key` 与 origin。
2. 短事务锁主体并查原键。命中则重放或按 `MODEL_SAVE_CLOSED`、410 处理。
3. 无命中时释放事务，在锁外规范化输入并准备业务密文与比较 vault。
4. 重新开事务，锁主体与原键，锁目录，锁 Provider 并比较 `expectedRevision` 与完整模型行集合。
5. 同事务写密文、修订、模型行、快照、配置版本、profile_links、head 与回执，提交。
6. 新建返回 201，更新返回 200，重放返回 200。

### close 正常路径

close 与保存争同一槽位。已提交或已拒绝时返回原回执；空槽位写入 `closed_without_save`；持槽竞争或提交未知返回 503。close 不解密 Key，也不检查 Provider 新修订。

### 导入正常路径

导入先取单例锁并查原键，再按 owner ID 排序锁账号，取目录锁，插入模板与执行版本、绑定默认、写回执，提交。任一步失败整体回滚，不留下半套依赖。

### 恢复场景

| 场景 | 预期结果 |
| --- | --- |
| 同键同输入 20 并发 | 只出现一个供应商修订、一套模型行、一个业务密文、一个 vault、一条回执；所有确认响应指向同一 `saveId`。 |
| 同键不同 Key 或不同模型集合 | 有权比较后返回 409 `IDEMPOTENCY_CONFLICT`，不覆写原请求，也不使用新 Key 执行旧操作。 |
| 秘密插入后业务写入失败 | 密文、可用性、目录、修订与回执全部回滚；包装次数预扣保留，不退还。 |
| 保存先提交，close 随后 | close 返回原 `committed` 回执，不撤销配置。 |
| close 先提交，合法迟到保存 | 返回 409 `MODEL_SAVE_CLOSED`，不写新密文、修订或供应商。 |
| 提交成功但响应丢失 | 原键查询最终返回原回执；期间 GET 的一次 404 不改变结论。 |
| 原记录被清理 | 有权请求返回 410 `MODEL_SAVE_RESULT_REMOVED`；业务 Key 不因回执清理被销毁。 |
| 导入提交未知 | 用原 `importId` 与同一清单重试；同键异内容冲突，不自动换键。 |

| 模型配置版本与项目固定配置 | `repomesh_projects`，B03 既有；本批只通过 `CatalogWriter` 登记，不复制解析器。 |
| 执行版本来源元数据与导入回执 | 本批 `repomesh_sources` 表。 |
| 模型测试、应用、Issue 与运行 | 不在本批。B05、B06 及后续批次不得在本批表上另建第二套 operation 框架。 |

## 设计理由

保存的原子性来自一个短事务和一个唯一槽位。没有它，用户双击或丢响应重试会产生两个供应商或半套模型行，后续项目会引用到不确定来源。修订不可变让旧项目、旧回执和旧测试始终能定位当时的参数，不受后来编辑影响。

Key 的比较材料与业务密文分开，使原操作重放不依赖业务 Key 当前是否可用。维护入口可以清理回执正文，但键占位保留，避免旧请求在清理后重新获得保存资格。

导入走部署身份而非浏览器，是因为模板、网络策略与默认绑定是部署事实。清单不接受任意命令、挂载或明文秘密，执行环境的创建与运行仍属后续批次。

## 验证清单

以下是可观察行为的预期结果，不是本次运行的测试记录。B04 的 S01 到 S12 已有真实 PostgreSQL 证据，见 [B04 验收报告](../development/2026-09-13-b04-acceptance-01/README.md) 与 [设计验收映射](../development/2026-09-13-b04-b06-design-01/ACCEPTANCE.md)。本次写作没有重跑这些用例。

| 检查 | 预期观察 |
| --- | --- |
| 新建保存 | 返回 201 与完整 `committed` 回执，详情能读到同一 `providerRevision`。 |
| 更新保存 | 提供正确 `expectedRevision` 时返回 200，`head_revision` 前进且旧修订仍可读。 |
| 修订冲突 | 返回 409 `PROVIDER_REVISION_CONFLICT` 且回执已持久；随后同键重放返回同一拒绝。 |
| 校验失败 | 返回 422 且不占用永久槽位；修正后可重新提交同一键。 |
| 列表分页 | `limit` 为 1 时返回 `nextCursor`，用该游标继续不重复也不跳页；伪造或过期游标分别返回 400 与 409。 |
| 详情 secret 分支 | 正常根下返回 `available`；销毁或停用后返回 `unavailable`；根缺失时返回 `unknown`；不返回明文或尾号。 |
| close 竞争 | 保存赢时 close 回 `committed`；close 赢时迟到保存回 `MODEL_SAVE_CLOSED`；两次 close 返回同一 `closedAt`。 |
| 导入重放 | 同 `importId` 同清单返回原回执且不推动 head；异内容返回 2 号退出码与 `IMPORT_CONFLICT`。 |
| 导入角色 | 非部署角色返回 `DEPLOYMENT_FORBIDDEN`；清单包含未知字段时拒绝且不写任何行。 |
| 锁序 | 同 owner 的交互写与导入交错时不出现目录与账号反向加锁；来源导入先锁单例，再按 ID 排序锁账号。 |
| 清理 | 清理后同键 GET 返回 410，旧键不能新建供应商，业务密文仍保留。 |

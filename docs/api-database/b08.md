## 证据分类与判定

证据分六类。每类只能支撑它在表中列出的结论，跨类替代属于无效验收。

| 类别 | 典型产物 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| 静态核对 | 链接检查、字段表与 JSON 示例比对、声明解析 | 文档与契约一致 | 任何运行行为 |
| 单元与接口测试 | `go test`、前端测试输出 | 本地逻辑与解析 | 真实数据库、浏览器与外部权限 |
| 真实数据库集成 | 独立 PostgreSQL 上的迁移、约束与并发用例 | 事务、唯一性与迁移行为 | GitHub 权限、模型与房间就绪 |
| 浏览器端到端 | 截图、页面状态记录、网络记录 | 页面恢复、缓存清理与晚到响应隔离 | 服务端核权是否被绕过 |
| 配套发布 | `release.json`、哈希核对、三入口版本输出 | 构建一致性与包完整性 | 业务验收与真实外部能力 |
| 真实外部 | 真实账号、真实模型或真实上游往返证据 | 对应外部路径可用 | 其他未覆盖路径 |

判定规则：PASS 要求命令或浏览器步骤、退出码或观察状态、原始输出或截图、清理结果齐全；SKIP 记录跳过原因与影响；FAIL 记录现象、最小复现并回交拥有批次；BLOCKED 只在依赖尚未采用或尚未实现时使用；无证据的条目保持 NOT_RUN。设计完成、构建通过与文档一致都不是 PASS。

## 执行顺序

1. 冻结基线，记录 `git rev-parse HEAD` 与 `git status`；工作区有未提交修改时逐文件记录并说明来源，不能只写 HEAD。
2. 核对工具版本与锁文件状态，确认前端依赖按锁文件安装。
3. 运行前端类型检查、测试与构建，保存原始输出。
4. 运行 Go 构建、测试与静态检查；数据库集成用例使用独立临时数据库并保存连接范围，不记录真实凭据。
5. 对全新数据库与旧版本数据库分别执行迁移检查，保存状态输出与拒绝分支。
6. 用新版本标签构建配套包，核对 `release.json` 哈希与三个入口版本。
7. 从配套目录启动 Web 与 coordinator，核对探针、资源路径与未接入状态。
8. 按矩阵执行浏览器用例，覆盖正常路径、恢复路径、失权与换账号。
9. 执行故障注入用例，优先覆盖丢响应、并发、重启与游标场景。
10. 清理临时数据库、目录、进程与浏览器上下文，记录清理结果。
11. 归档证据目录并做一次独立只读复核，确认引用、哈希与结论一致。

### 迁移

数据库命令与状态输出见 [main.go](../../cmd/repomesh-web/main.go) 第 91 至 96 行与第 138 至 161 行。检查规则见 [migrations.go](../../internal/database/migrations.go) 第 58 至 97 行。验收入口如下。

1. 全新数据库：`db check` 返回非零且状态为 `pending`；`db migrate` 后状态为 `current`，随后 `db check` 为零。
2. 旧版本数据库：升级前 `db check` 必须显示待应用迁移；应用后无残留 pending。
3. 历史不符：篡改版本名、校验和或制造非连续版本时整体拒绝，不部分应用。
4. 进程行为：已配置认证的 Web 与 coordinator 不自动迁移；迁移只能由显式命令执行。
5. 回退与备份：本批不新增回退协议。验收记录只保存检查结论与状态值，不把回滚脚本写成已存在。

## 证据归档

证据以文件形式保存，不写产品数据库表，不新增 `acceptance_runs` 之类的运行记录。

目录规则沿用 `docs/development/日期-主题/`。一次验收运行包含以下文件。

```text
docs/development/2026-09-20-b08-acceptance-01/
  README.md          结论、范围、环境、逐项结果、未通过项与限制
  checks.json        机器可读的命令、退出码、结果与证据引用
  browser/           浏览器用例截图与页面状态记录
  logs/              去秘密后的服务与构建日志
  release/           release.json 副本与哈希核对结果
```

`README.md` 至少包含结论、基线提交、执行时间、环境版本、用例编号与结果、未执行项、剩余风险与清理结果。`checks.json` 建议使用以下键，具体命名可以调整，但语义不得丢失。

```json
{
  "runId": "b08-acceptance-01",
  "baseline": {"commit": "FULL_SHA", "dirty": false},
  "executedAt": "2026-09-20T00:00:00Z",
  "environment": {"os": "linux", "arch": "amd64", "go": "GO_VERSION", "node": "NODE_VERSION"},
  "results": [
    {"case": "B08-A01", "status": "PASS", "command": "COMMAND", "exitCode": 0, "evidence": "browser/a01.png"}
  ],
  "externalAcceptance": "NOT_RUN",
  "businessReady": false,
  "cleanup": "PASS"
}
```

证据纪律：命令必须可重放；日志中的秘密、Cookie、连接串与 Key 必须替换为 `[REDACTED]`；截图不得包含真实凭据或他人正文；测试产生的临时数据库、目录与进程必须记录清理结果；失败与跳过项保留原样，不在后续运行中改写。

没有真实运行时，`externalAcceptance` 必须写 `NOT_RUN` 并说明缺什么。B02 的真实账号项、B05 的模型请求与 B09 及以后任何运行能力都不因 B08 的本地通过而变成可用。

# B02 登录会话、仓库发现与认证秘密基础（已有实现；外部验收 PAUSED_BY_USER）

B02 让用户用 GitHub 登录、维持本地会话、在同一外部账号上重连，并看到当前凭据覆盖范围内的可参与仓库。用户的 Key 与令牌不落明文：认证材料用信封加密保存，包装根来自部署目录中的私密文件。本批本地单元 `B02.1` 至 `B02.5` 已 `LOCAL_VERIFIED`，整批状态为 `IN_PROGRESS`；真实 GitHub App 外部验收 `NOT_RUN`，用户决定暂停（`PAUSED_BY_USER`）。

采用范围见 [B02 认证实施采用记录](../current/b02-authentication-adoption.md)，本地证据见 [B02 批次记录](../development/2026-09-12-batch-02/README.md) 与 [标准验收](../development/2026-09-12-batch-02/verification-02/checks.json)。字段来源是 [认证浏览器候选](../current/authentication-browser-api-draft.md)（该文件头仍标 `status: proposed`，但采用记录已接纳 B02 子集；按 [AGENTS 规则](../../AGENTS.md) 与 [采用记录](../current/b02-authentication-adoption.md)，以采用范围而不是文件标签判断）。配置与部署步骤见 [认证开发说明](../current/authentication-development.md)。跨批公共规则见 [公共规则](./foundations.md)。

## 公共约定

七个端点都走 `registerAuth` 装配，见 [auth.go](../../internal/web/auth.go) 第 27 行。每个端点共用以下边界。

| 约定 | 行为 |
| --- | --- |
| 认证未配置 | 全部端点返回 503 `AUTH_NOT_CONFIGURED`；正常启动不注册业务数据访问。 |
| 请求超时 | 每个请求 15 秒上下文超时，见 [auth.go](../../internal/web/auth.go) 第 40 行。 |
| 响应头 | 统一 `Cache-Control: no-store` 与 `Referrer-Policy: no-referrer`。 |
| 错误体 | `{"error":{"code","message","details"}}`，由 [auth.go](../../internal/web/auth.go) 第 179 行的 `authError` 生成；未识别错误一律 503 `RESULT_UNCONFIRMED`。项目接口另用 `fieldErrors` 与 `requestId`，见 [b03.md](./b03.md)。 |
| 请求体 | 只接受 `application/json`（可带 `charset=utf-8`），上限 256 KiB；过大返回 413 `PAYLOAD_TOO_LARGE`，非法 JSON 或非对象返回 422 `VALIDATION_FAILED`，见 [auth.go](../../internal/web/auth.go) 第 151 行。 |
| Origin | 所有 `POST` 必须携带单值 `Origin` 且等于部署 origin，否则 403 `ORIGIN_REJECTED`，见 [auth.go](../../internal/web/auth.go) 第 36 行。 |
| Cookie | 会话 Cookie 名 `__Host-repomesh-session`，绑定 Cookie 名 `__Host-repomesh-binding`；均为 `Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/`，见 [auth.go](../../internal/web/auth.go) 第 176 行。同名 Cookie 必须恰好一个，否则该次读取视为未携带。 |
| CSRF | 会话读取返回 `csrfToken = SHA-256("repomesh-csrf:" + cookie)`，见 [session.go](../../internal/access/session.go) 第 28 行；写操作以常量时间比较校验，见第 37 行。 |
| 会话有效性 | 会话未撤销、账号未禁用、会话未过期、空闲不超过 30 分钟、绑定未过期，且会话代次等于绑定身份代次，见 [session.go](../../internal/access/session.go) 第 16 行。 |
| 账号隔离 | 所有读写以当前认证 actor 为准；查询他人资源按不可见处理。 |

## HTTP API

### GET /api/session

#### 调用方与授权

页面加载、恢复与任何需要当前身份的前端流程。调用者必须携带有效会话 Cookie；不接受客户端 userId。

#### 输入

无查询参数。Cookie 缺失、重名或无效时不进入业务逻辑，直接 401。

#### 返回

`200 OK`：

```json
{"user":{"id":"usr_1","displayName":"示例用户"},"githubConnection":{"status":"connected","observedAt":"2026-09-10T00:00:00Z"},"csrfToken":"session-bound-value"}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `user.id` | string | 稳定本地主体 ID。 |
| `user.displayName` | string | 展示名，随每次登录更新。 |
| `githubConnection.status` | string | `connected`、`missing` 或 `unknown`；`connected` 只在刷新状态空闲、访问令牌未过期且观察时间在 60 秒内出现，见 [session.go](../../internal/access/session.go) 第 30 行。 |
| `githubConnection.observedAt` | RFC3339 或 null | 最近一次连接观察时间。 |
| `csrfToken` | string | 本次会话的防伪值，写操作必须原样回传。 |

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 401 | `AUTHENTICATION_REQUIRED` | Cookie 缺失、重名、已撤销、已过期、账号禁用或代次不符。 |
| 503 | `RESULT_UNCONFIRMED` | 数据库读取失败。 |
| 503 | `AUTH_NOT_CONFIGURED` | 进程未配置认证。 |

#### 并发与重放

每次读取都会更新 `last_active_at`，因此并发读取共享同一空闲窗口，见 [session.go](../../internal/access/session.go) 第 16 行。读取不修改连接与尝试，可安全重放。`connected` 不证明任何仓库当前可读，也不证明某次重连成功。

#### 设计理由

CSRF 值由会话 Cookie 派生而不是单独存表：撤销会话即失效，不需要额外清理步骤。连接状态用观察时间表达新鲜度，避免把“上次成功”当成当前事实。

### POST /api/auth/github/login

#### 调用方与授权

未登录用户发起 GitHub 授权。已有有效会话时返回 409，必须先退出或使用重连。

#### 输入

| 位置 | 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- | --- |
| 头 | `Origin` | string | 是 | 单值且等于部署 origin。 |
| 头 | `Idempotency-Key` | string | 是 | 单值，UUID 形状（小写十六进制）作为 `attemptId`。 |
| 体 | `destination` | object | 是 | 严格联合类型，见下。 |

Destination 只接受以下形状，每行字段全部必填且只允许列出字段，解析见 [destination.go](../../internal/access/destination.go) 第 99 行：

| 形状 | 必填字段 | 首批是否有目标解析 |
| --- | --- | --- |
| `{"kind":"home"}` | 无 | 是，固定 `/`。 |
| `{"kind":"project"}` | `projectId` | 是，B03 解析项目页面。 |
| `{"kind":"issue"}` | `projectId`、`issueId` | 否；当前 `nextPage` 为 null。 |
| `{"kind":"conversation"}` | `projectId`、`conversationId` | 否；只读会话属后续批次。 |
| `{"kind":"operation","operationKind":"project_create"}` | `operationId` | 是，B03 解析创建恢复页。 |
| `{"kind":"operation","operationKind":"project_update"}` | `projectId`、`operationId` | 是，B03 解析更新恢复页。 |
| `{"kind":"operation","operationKind":"provider_save"}` | `operationId` | 是，B04 解析模型保存恢复页。 |
| `{"kind":"operation","operationKind":"issue_create"}` | `projectId`、`operationId` | 否。 |
| `{"kind":"operation","operationKind":"model_test"}` | `operationId` | 否。 |
| `{"kind":"operation","operationKind":"model_apply"}` | `projectId`、`operationId` | 否。 |

ID 最长 128 个 Unicode 标量，不接受 `.`、`..`、路径分隔符、控制字符或百分号编码变体。`conversation_message` 不在当前联合类型内，首批收到即 422 `VALIDATION_FAILED`，与[认证稿 §8](../current/authentication-browser-api-draft.md) 的后续扩展说明一致。

#### 返回

首次成功 `201 Created`，同输入重放 `200 OK`：

```json
{"attemptId":"0a2a5d23-398b-4e46-865b-fc9a1dd15738","authorizationUrl":"https://github.com/login/oauth/authorize?...","expiresAt":"2026-09-11T12:10:00Z","resultPage":"/auth/result/0a2a5d23-398b-4e46-865b-fc9a1dd15738"}
```

建立新浏览器绑定时同时下发 `__Host-repomesh-binding`（7 天）。字段结构见 [types.go](../../internal/access/types.go) 第 70 行；生成逻辑见 [start.go](../../internal/access/start.go) 第 198 行。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 403 | `ORIGIN_REJECTED` | Origin 缺失、重名或不匹配。 |
| 422 | `VALIDATION_FAILED` | 缺少幂等键、键形状非法或 Destination 非法。 |
| 409 | `SESSION_ALREADY_ACTIVE` | 已有有效会话仍发起登录。 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一绑定与键的既有尝试用途或 Destination 不同。 |
| 409 | `ATTEMPT_IN_PROGRESS` | 既有尝试已领取交换、非 `pending` 或已过期。 |
| 429 | `RATE_LIMITED` | 每绑定每分钟 5 次，见 [start.go](../../internal/access/start.go) 第 131 行与第 132 行；响应带 `Retry-After: 60`。 |
| 503 | `RESULT_UNCONFIRMED` | 数据库、秘密存储或随机源不可用。 |

#### 并发与重放

作用域是浏览器绑定摘要加用途加 `attemptId`，见 [start.go](../../internal/access/start.go) 第 142 行。同一键与同一 Destination 在尝试仍为 `pending` 且未过期时返回同一 `authorizationUrl`，见第 157 行的 `replayStart`。同一绑定上的新尝试会把旧未完成尝试置为 `superseded`／`NEWER_ATTEMPT` 并推进尝试代次，见第 134 行；旧标签页不能继续用旧 state 完成登录。`state` 与 PKCE verifier 密封保存，只有摘要进入数据库索引。

#### 设计理由

授权 URL 里带有浏览器绑定的 state，重放返回同一条链接可以让“请求已经发出但响应丢失”的页面继续原尝试，而不是再开一次授权。绑定 Cookie 7 天不滑动，避免旧浏览器身份在用户离开后被无限续期。

### POST /api/auth/github/reconnect

#### 调用方与授权

已登录用户在同一外部账号上重连，例如访问令牌被撤销后修复连接。要求有效会话、CSRF 与属于该会话的绑定 Cookie。

#### 输入

与登录相同，另加：

| 位置 | 字段 | 必填 | 约束 |
| --- | --- | --- | --- |
| 头 | `X-CSRF-Token` | 是 | 必须等于当前会话的 `csrfToken`，否则 403 `CSRF_REJECTED`。 |
| Cookie | `__Host-repomesh-binding` | 是 | 摘要必须等于会话绑定，否则 403 `ORIGIN_REJECTED`，见 [start.go](../../internal/access/start.go) 第 42 行。 |

#### 返回与错误

成功形状与登录相同。额外限流为每账号每分钟 10 次；尝试记录 `expected_github_id` 与 `expected_connection_revision`，见 [start.go](../../internal/access/start.go) 第 118 行。回调阶段若外部账号与预期不同，尝试终结为 `rejected`／`ACCOUNT_MISMATCH`，原连接保留，见 [callback.go](../../internal/access/callback.go) 第 118 行。

#### 并发与重放

重放规则与登录一致。若期间连接修订已经变化（其他重连先提交），旧尝试被置为 `superseded`／`NEWER_ATTEMPT`，不会覆盖新连接，见 [callback.go](../../internal/access/callback.go) 第 181 行。

#### 设计理由

重连是修复连接而不是切换账号。记录原外部账号并拒绝账号不一致，可以避免一次误点把项目与历史默默迁移到另一个 GitHub 身份。

### GET /api/auth/github/callback

#### 调用方与授权

GitHub 授权服务器重定向到本端点。授权依据是浏览器绑定 Cookie 加尝试的 state 摘要；该请求不使用业务 CSRF。

#### 输入

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `state` | string | 是 | 尝试 state 原文；查询串中出现多次时按非法处理，见 [auth.go](../../internal/web/auth.go) 第 87 行。 |
| `code` | string | 条件必填 | 授权码，最长 2048。 |
| `error` | string | 否 | GitHub 错误码，最长 128。 |
| Cookie | `__Host-repomesh-binding` | 是 | 浏览器绑定。 |

#### 返回

无论成功、取消或失败，都以 `303 See Other` 重定向，见 [auth.go](../../internal/web/auth.go) 第 99 行。可映射到尝试时进入 `/auth/result/{attemptId}`，否则进入 `/login`。确认成功时同时下发 12 小时会话 Cookie。

#### 状态转移

| 阶段 | 写入 | 说明 |
| --- | --- | --- |
| 校验绑定与 state | 无 | 不匹配时按非法处理，直接回登录页。 |
| 用户取消 | `cancelled`／`USER_CANCELLED` | 见 [callback.go](../../internal/access/callback.go) 第 51 行。 |
| 其他供应商错误或缺少 code | `unknown`／`EXCHANGE_UNCONFIRMED` | 未知不等于失败。 |
| 有效 code | `exchanging` | 先提交领取交换责任，再在事务外调用 GitHub，见第 62 行。 |
| 交换成功 | `identity_pending` | 令牌密封保存，`token_ref` 指向密文版本。 |
| 身份核实成功 | `confirmed` | 账号、连接修订、会话与尝试在同一事务落库，见第 191 行。 |

#### 错误与状态码

回调处理器不返回 JSON 错误体：它总是重定向，见 [auth.go](../../internal/web/auth.go) 第 99 行。内部失败表现为进入结果页并由 `GET /api/auth/attempts/{id}` 报告 `unknown`。这一行为与[认证稿 §4](../current/authentication-browser-api-draft.md) 的“能可信映射到原尝试的失败也到站内结果页”一致。

#### 并发与重放

只有一次交换责任：其他并发回调在 `state != pending` 时直接返回现有结果页，不会重复使用 code，见 [callback.go](../../internal/access/callback.go) 第 48 行。身份确认阶段的代次校验不通过时，回调直接返回，不签出会话，见第 165 行；把旧尝试写为 `superseded` 的路径分别见 [start.go](../../internal/access/start.go) 第 134 行、[session.go](../../internal/access/session.go) 第 74 至 79 行，以及 [callback.go](../../internal/access/callback.go) 第 181 至 188 行的连接修订冲突处理。已提交但 Cookie 未到达浏览器时，尝试为 `confirmed` 而会话为 401；页面只能重新登录。

#### 设计理由

把外部网络调用放在事务之外、把责任领取放在事务之内，可以避免长事务持锁；同时保留“谁负责这次交换”的唯一记录，使重复回调无法重复换码。

### GET /api/auth/attempts/{id}

#### 调用方与授权

登录恢复页与重连结果页。查询依据是尝试所属的浏览器绑定；重连另要求当前会话属于原 actor。

#### 输入

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 路径 `id` | UUID 形状 | 是 | `attemptId`。 |
| Cookie | `__Host-repomesh-binding` | 是 | 摘要用于定位尝试，见 [callback.go](../../internal/access/callback.go) 第 220 行。 |
| Cookie | `__Host-repomesh-session` | 否 | 匿名登录查询可省略；重连查询必需。 |

#### 返回

`200 OK`：

```json
{"attemptId":"0a2a5d23-398b-4e46-865b-fc9a1dd15738","purpose":"reconnect","state":"confirmed","reasonCode":null,"observedAt":"2026-09-11T12:03:00Z","connection":{"committedRevision":"gc_8","isCurrent":true},"nextPage":"/"}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `purpose` | string | `login` 或 `reconnect`。 |
| `state` | string | 对外的 `pending`、`unknown`、`confirmed`、`cancelled`、`rejected`、`expired`、`superseded`；存储中的 `exchanging` 与 `identity_pending` 对外统一显示 `unknown`，见 [callback.go](../../internal/access/callback.go) 第 254 行。 |
| `reasonCode` | string 或 null | `USER_CANCELLED`、`ACCOUNT_MISMATCH`、`EXCHANGE_UNCONFIRMED`、`ATTEMPT_EXPIRED`、`NEWER_ATTEMPT` 等。 |
| `observedAt` | RFC3339 或 null | 最近一次服务端观察。 |
| `connection` | object 或 null | 仅已核原 actor 的重连确认回执返回 `{committedRevision,isCurrent}`；`isCurrent` 是本次查询时的比较结果。 |
| `nextPage` | string 或 null | 当前会话有效并完成目标解析时的站内地址；否则 null，不透露受限目标。 |

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 404 | `RESOURCE_NOT_FOUND` | 无绑定 Cookie、ID 非法、尝试不存在或跨 actor 的重连查询。 |
| 401 | `AUTHENTICATION_REQUIRED` | 重连查询缺少有效会话。 |
| 410 | `AUTH_ATTEMPT_RESULT_REMOVED` | 尝试创建超过 24 小时，见 [callback.go](../../internal/access/callback.go) 第 251 行。 |
| 503 | `RESULT_UNCONFIRMED` | 数据库或绑定读取失败。 |

#### 并发与重放

查询不做外部交换、不刷新令牌、不写业务数据；重复查询返回同一历史状态（除 `expired` 的时间判定与 `isCurrent`）。`unknown` 不随经过时间变成 `rejected`。

#### 设计理由

把“已确认但 Cookie 丢失”“交换未确认”和“用户取消”分开，页面才能给出正确下一步。24 小时后清理非秘密结果，避免旧尝试被当作新授权凭据。

### POST /api/auth/logout

#### 调用方与授权

当前会话注销。要求 Origin 与会话绑定的 CSRF。

#### 输入

请求体必须是 `{}` 形状的 JSON 对象。头包括单值 `Origin` 与 `X-CSRF-Token`。

#### 返回

`204 No Content`，无响应体。

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 403 | `CSRF_REJECTED` | CSRF 不匹配。 |
| 403 | `ORIGIN_REJECTED` | Origin 缺失、重名或不匹配。 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Content-Type 不是 `application/json`。 |
| 422 | `VALIDATION_FAILED` | 请求体不是 JSON 对象，或含未知字段（解码禁止未知字段）。 |
| 204 | 无 | 会话已失效或不存在时幂等成功，见 [session.go](../../internal/access/session.go) 第 44 行。 |

#### 并发与重放

注销在同一事务中撤销当前会话；只有当前绑定代次仍等于请求会话代次时才推进 `identity_generation` 与 `attempt_generation` 并把该代次的未完成尝试置为 `superseded`，见 [session.go](../../internal/access/session.go) 第 62 行。响应不删除 Cookie；旧 Cookie 由服务端按撤销状态拒绝。

#### 设计理由

晚到的注销响应不应清掉一个更新的登录 Cookie。服务端代次仍然保证旧 Cookie 无法授权，浏览器状态交给下一次会话读取纠正。

### GET /api/repositories

#### 调用方与授权

项目创建页的仓库选择器与发现状态展示。调用者必须登录；只返回当前凭据范围内可披露的仓库。

#### 输入

| 参数 | 类型 | 必填 | 默认 | 约束 |
| --- | --- | --- | --- | --- |
| `q` | string | 否 | 空 | 最多 200 个 Unicode 标量；大小写不敏感子串匹配。 |
| `cursor` | string | 否 | 空 | 最多 128 字符，且为服务端先前返回的值。 |
| `limit` | integer | 否 | 50 | 1 到 100。 |

解析见 [auth.go](../../internal/web/auth.go) 第 133 行；三个参数都必须单值，其他键或重复键返回 422 `VALIDATION_FAILED`。

#### 返回

`200 OK`：

```json
{"items":[{"id":"repo_00000000000000000123","displayName":"example/orders","userParticipation":{"status":"allowed","reasonCodes":[],"observedAt":"2026-09-10T00:00:00Z"},"appCapability":{"status":"denied","reasonCodes":["APP_PERMISSION_MISSING"],"observedAt":"2026-09-10T00:00:00Z"}}],"nextCursor":null,"coverage":{"status":"partial","reasonCodes":["APP_INSTALLATION_SCOPE"],"observedAt":"2026-09-10T00:00:00Z"}}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `items[].id` | string | 稳定本地仓库 ID，形如 `repo_` 加 20 位 GitHub 数字 ID。 |
| `items[].displayName` | string | `owner/name`。 |
| `items[].userParticipation` | object | `allowed`、`denied` 或 `unknown` 加 `reasonCodes`、`observedAt`。 |
| `items[].appCapability` | object | 同一形状；App 能力核查失败可为 `unknown`。 |
| `nextCursor` | string 或 null | 继续位置；为 null 只表示当前批次遍历结束。 |
| `coverage.status` | string | 当前实现固定 `partial`，原因码固定 `APP_INSTALLATION_SCOPE`，见 [discovery.go](../../internal/access/discovery.go) 第 132 行。 |

#### 错误与状态码

| 状态 | code | 触发条件 |
| --- | --- | --- |
| 400 | `INVALID_CURSOR` | 游标不存在、属于其他 actor，或查询文本与游标创建时不同。 |
| 409 | `CURSOR_EXPIRED` | 批次过期，或连接修订／访问代次已变化。 |
| 422 | `VALIDATION_FAILED` | 查询参数非法。 |
| 503 | `AUTHORIZATION_UNCONFIRMED` | 本条连接无法确认，或全部条目都无法确认且没有可披露结果，见 [credential.go](../../internal/access/credential.go) 第 25 行与 [discovery.go](../../internal/access/discovery.go) 第 163 行。 |
| 503 | `RESULT_UNCONFIRMED` | 批次尚无成功扫描结果或数据库读取失败，见 [discovery.go](../../internal/access/discovery.go) 第 98 行。 |

#### 并发与重放

首页请求会复用同 actor、同连接修订、同访问代次、同查询的未完成或未交付批次，否则创建新批次并设 10 分钟有效期，见 [discovery.go](../../internal/access/discovery.go) 第 78 行。带游标的请求只消费游标所属批次。每页对超过 60 秒的观察重新核验仓库 ID；若全部条目都无法确认且没有可披露结果，返回 503 而不是空列表，见第 163 行。coordinator 以 `claim_version` 与 15 秒租约续扫，过期领取者不能覆盖新批次，见 [worker.go](../../internal/access/worker.go) 第 54 行。

#### 设计理由

把发现做成持久批次而不是一次请求遍历全部仓库，让网络慢或页面关闭都不会丢失已发现的稳定 ID。固定 `partial` 覆盖状态是对用户诚实的表达：单一 App 安装范围之外仍可能有受邀私仓缺席。

## 数据库表

本批拥有 `repomesh_secrets` 的四个基础表与 `repomesh_access` 的九个表。`repomesh_secrets.versions` 同时被 B04 的模型密钥使用，但表结构与根管理属于本批；B03 的 `0004_projects.sql` 为它补了 `(version_id, owner_kind, owner_id, purpose)` 唯一约束以支撑配置引用，见 [b03.md](./b03.md)。

### repomesh_secrets.root_keys

#### 用途与写入者

包装根注册表。写入者是秘密存储初始化（注册与激活）与轮换预留；读取者是所有加解密路径。DDL 见 [0002_auth_secrets.sql](../../internal/database/migrations/0002_auth_secrets.sql)。

| 项目 | 状态 |
| --- | --- |
| 表 | 已实现 |
| 契约 | S01／S02 认证秘密子集已采用 |
| 字段 | 无新增，本文件只整理既有事实 |

#### 字段

| 字段 | 类型 | 必填 | 约束 | 人话含义 |
| --- | --- | --- | --- | --- |
| `root_id` | text | 是 | 主键，长度 1 到 128 | 部署人员给包装根起的名字。 |
| `fingerprint` | bytea | 是 | 唯一，长度必须为 32 | 根密钥的 SHA-256，用来发现同 ID 换了密钥文件。 |
| `active_wrap` | boolean | 是 | 默认 `false` | 是否为当前写入使用的根。 |
| `wrap_count` | bigint | 是 | 默认 0，范围 0 到 1000000 | 已预扣的包装次数，用于轮换提醒。 |
| `registered_at` | timestamptz | 是 | 默认 `now()` | 首次注册时间。 |
| `activated_at` | timestamptz | 否 | 激活时必须非空 | 成为当前根的时间。 |
| `retired_at` | timestamptz | 否 | 退休后非空 | 不再作为当前根的时间。 |

表级约束：`CHECK (NOT active_wrap OR (activated_at IS NOT NULL AND retired_at IS NULL))`；部分唯一索引 `one_active_root ON ((true)) WHERE active_wrap` 保证同一时刻只有一个当前根。

#### 事务关系与状态转移

注册在一个事务中完成：取固定 advisory lock、锁当前活动根、逐个比对指纹、确认所有在用密文所需的根都在配置里、校验自检信封，再切换 `active_wrap` 与 `retired_at`，见 [roots.go](../../internal/secrets/roots.go) 第 16 行。状态转移为“注册 → 激活 → 退休”；退休根保留，用于解密历史密文。

#### 删除与保留

根行不删除。删除或替换根文件会导致启动失败；如需轮换，先把新根加入配置并设为 `activeRootId`，由 coordinator 逐批重加密旧密文。

#### 设计理由

指纹让“同名不同密钥”在启动时暴露，而不是等到某次解密失败。活动根唯一约束把并发启动的竞争收敛为确定结果。

### repomesh_secrets.versions

#### 用途与写入者

密文版本表。写入者是 `Seal`、`Destroy` 与 `Rewrap`；读取者是 `Open`、`InspectVersion` 与各业务域的可用性投影。本批使用认证用途，B04 增加 `model-provider-key` 与 `operation-input` 用途。

#### 字段

| 字段 | 类型 | 必填 | 约束 | 人话含义 |
| --- | --- | --- | --- | --- |
| `version_id` | text | 是 | 主键 | 密文版本身份。 |
| `owner_kind` | text | 是 | 长度 1 到 128 | 归属类型，例如 `actor`、`auth-attempt`、`github-app`。 |
| `owner_id` | text | 是 | 长度 1 到 256 | 归属主体 ID。 |
| `purpose` | text | 是 | 长度 1 到 128 | 用途白名单在 Go 侧强制，见 [store.go](../../internal/secrets/store.go) 第 76 行。 |
| `format_version` | integer | 是 | 必须为 1 | 信封格式版本。 |
| `ciphertext` | bytea | 条件必填 | 未销毁时非空且不短于 28 字节 | AES-256-GCM 密文。 |
| `wrapped_dek` | bytea | 条件必填 | 未销毁时长度必须为 60 | 被根密钥包裹的数据密钥。 |
| `root_id` | text | 是 | 外键引用 `root_keys(root_id)` | 当前包裹该 DEK 的根。 |
| `wrap_revision` | bigint | 是 | 默认 1 且大于 0 | 包裹修订号，轮换时递增。 |
| `created_at` | timestamptz | 是 | 默认 `now()` | 创建时间，孤儿清理依据。 |
| `destroyed_at` | timestamptz | 否 | 销毁后非空 | 销毁墓碑时间。 |

表级约束要求“未销毁”与“已销毁”两种形状互斥：销毁后 `ciphertext` 与 `wrapped_dek` 必须为 NULL，密文不可恢复。索引 `versions_by_root(root_id, version_id)` 支撑轮换扫描。

#### 事务关系与状态转移

`Seal` 先持久预扣包装次数再插入密文行，见 [store.go](../../internal/secrets/store.go) 第 98 行与第 133 行。`Destroy` 在同一事务里清空密文并停用可用性，且对已销毁行幂等，见第 226 行。`Rewrap` 在事务外完成加解密，事务内要求活动根未变并以 `root_id` 与 `wrap_revision` 比较交换，见第 250 行。状态转移只有“创建 → 可用／停用 → 已销毁”，没有复活路径。

#### 删除与保留

行保留作为墓碑，密文清除。被认证尝试、连接或 App 凭据引用的版本不能提前销毁；孤儿清理只处理创建超过 15 分钟且没有任何引用的行，见 [cleanup.go](../../internal/access/cleanup.go) 第 20 行。

#### 设计理由

把“密文还在”与“密钥可用”分成两行，使得轮换、停用与销毁可以独立推进；墓碑保证同一个版本 ID 不会在销毁后被重新解释成新密钥。

## 事务与恢复

| 场景 | 期望行为 | 依据 |
| --- | --- | --- |
| 同一键并发发起登录 | 只有一个尝试建立；另一个按原尝试重放或得到冲突 | [start.go](../../internal/access/start.go) 第 90 行 |
| 同键不同 Destination 或用途 | 409 `IDEMPOTENCY_CONFLICT`，不改绑原尝试 | 第 172 行 |
| 浏览器丢失绑定 Cookie | 明确从新登录开始；旧尝试按过期或代次失效，不重放业务 | [认证稿 §3](../current/authentication-browser-api-draft.md) |
| 回调重复到达 | 第二次不再换 code，直接回结果页 | [callback.go](../../internal/access/callback.go) 第 48 行 |
| code 交换结果未知 | 尝试终结为 `unknown`／`EXCHANGE_UNCONFIRMED`，不自动重用 code | 第 103 行 |
| 交换成功但进程崩溃 | 令牌已密封为 `token_ref`，coordinator 用代次匹配重试身份确认 | [worker.go](../../internal/access/worker.go) 第 24 行 |
| 确认已提交但 Cookie 丢失 | 查询返回 `confirmed` 而会话 401；页面重新登录 | [认证稿 §5](../current/authentication-browser-api-draft.md) |
| 重连期间连接被他人更新 | 旧尝试置为 `superseded`，不覆盖新连接 | [callback.go](../../internal/access/callback.go) 第 181 行 |
| 刷新响应丢失 | 连接进入 `unknown`，不假定失败也不假定成功 | [credential.go](../../internal/access/credential.go) 第 97 行 |
| 等待锁或数据库超时 | 请求按 503 `RESULT_UNCONFIRMED` 结束；写操作重试仍以原键查询 | [auth.go](../../internal/web/auth.go) 第 179 行 |
| 注销晚到 | 不回滚新会话；只有代次仍匹配时才推进失效 | [session.go](../../internal/access/session.go) 第 62 行 |
| 发现批次过期或撤权 | 409 `CURSOR_EXPIRED`，从第一页重新读取 | [discovery.go](../../internal/access/discovery.go) 第 95 行 |
| 孤儿密文 | 创建超过 15 分钟且无引用时销毁，保留墓碑 | [cleanup.go](../../internal/access/cleanup.go) 第 20 行 |
| 根文件被替换 | 启动时指纹或自检失败，拒绝服务 | [roots.go](../../internal/secrets/roots.go) 第 44 行 |

包装根轮换是“先解密、后比较交换”的流程：事务外完成加解密，事务内要求活动根未变且 `wrap_revision` 未变，见 [store.go](../../internal/secrets/store.go) 第 286 行。租约、代次与领取版本都只是调度事实，不表示某个进程已经停止或某个外部动作已经失败。

## 设计理由

把浏览器绑定、会话与尝试分成三个身份，使“浏览器还在”“用户已登录”“某次授权正在处理”可以分别撤销。绑定 7 天不滑动、会话 12 小时绝对加 30 分钟空闲、尝试 10 分钟，这三个期限对应不同风险：长期浏览器身份、日常工作会话、短时授权流程。

令牌与交换材料只用密文进入数据库，AAD 绑定版本 ID、归属、用途与根 ID，见 [crypto.go](../../internal/secrets/crypto.go) 第 23 行。这样即使同一份数据库被另一部署复制，密文也不能被错误归到别的账号或用途。

发现使用持久批次与稳定仓库 ID，让分页与续扫在页面关闭、进程重启后仍可继续；`partial` 覆盖状态比“空列表”更诚实，用户不会因为一次上游失败以为账号里没有仓库。

## 验证清单

以下为可观察的预期结果。本批已执行过一次 `LOCAL_VERIFIED` 证据；外部项仍待真实 App。

- 空库迁移到版本 3 后重复执行保持 `current`；历史篡改被拒绝，见 [标准验收](../development/2026-09-12-batch-02/verification-02/checks.json)。
- 未配置认证时 `GET /api/session` 返回 503 `AUTH_NOT_CONFIGURED`。

- 登录首次 201、同输入重放 200 且返回同一 `authorizationUrl`；同键不同 Destination 返回 409。
- 每绑定每分钟第 6 次发起返回 429 且带 `Retry-After`。

- 刷新令牌响应丢失后连接状态为 `unknown`，下一次请求先核查而不重发未知交换。
- 真实 GitHub：登录、取消、同账号重连、私仓发现与 App 权限观察。当前 `NOT_RUN`，属 `PAUSED_BY_USER`。

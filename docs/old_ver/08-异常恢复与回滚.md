# 08 · 异常、恢复与回滚

## 目标

异常必须有可查的原因、有界的处理过程和可确认的结果。用户不需要依靠重复点击或重新创建需求来解决卡住的工作。

## 功能需求

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| RCV-01 | 统一恢复事项 | 汇总执行中断、成员失联、交付冲突、验证失败和人工升级，展示严重程度、影响范围、证据版本、负责人及可用动作 |
| RCV-02 | 自动恢复判断 | 根据持续失联、最后进展、工作现场和尝试预算判断；一次短暂检查失败不直接换人 |
| RCV-03 | 恢复原会话 | 原成员与工作现场可用且工具支持时继续原工作；需要人工输入的情况先展示问题 |
| RCV-04 | 干净重试 | 原现场不可恢复时创建新尝试，绑定同一任务和新的有效输入，封存旧尝试 |
| RCV-05 | 同队换人 | 从同一仓库团队中选择健康、有空闲能力且符合要求的成员；显示替换理由与指派历史，不跨仓借用未经授权成员 |
| RCV-06 | 人工恢复决策 | 用户预览影响与动作，选择允许的重试、换人、冲突修复、计划修订、回滚、取消或人工处理；绑定当前证据 |
| RCV-07 | 交付冲突修复 | 基准变化或候选冲突形成独立事项，阻断交付，派发本仓修复任务，产生新候选后重新验证与审批 |
| RCV-08 | 恢复过程跟踪 | 展示发现、自动恢复、待决定、已批准、执行中、复核中、解决或失败；失败重试保留历史 |
| RCV-09 | 整组回滚预览 | 对整个交付组列出每仓状态、将采取的动作与顺序，填写原因并确认；不提供单仓随意撤回 |
| RCV-10 | 整组回滚执行 | 未发布成果停止发布；未合入候选关闭；已合入成果形成反向评审请求，按相反依赖顺序推进 |
| RCV-11 | 回滚冲突与复核 | 反向变更仍经过验证、检查和审批；冲突转修复事项，完成后重新确认整组一致性 |

RCV-03、RCV-04、RCV-07、RCV-09 至 RCV-11 为保留范围；RCV-01、RCV-02、RCV-05、RCV-06、RCV-08 为补齐范围，已有恢复能力与统一完整界面之间需要补足。

## 自动恢复规则

- 活跃工作仍有有效占用记录时，不重复发起第二个执行。
- 旧成员恢复在线后，其过期结果只能作为历史，不能改变当前任务或交付。
- 可用原会话优先于换人；成员不可用、现场不可恢复才考虑健康同队成员。
- 重试次数和换人次数受明确预算控制，预算耗尽、没有可用成员或证据相互矛盾时升级人工。
- 已取消需求、已终结或已被替代任务，不再自动启动恢复。
- 恢复不得增加仓库范围、访问权限或绕过原审核要求。

## 回滚确认内容

弹窗必须展示交付组名称、原因输入、受影响仓库、当前实际阶段、每仓恢复动作、逆序位置、尚未解决的冲突和后续审核要求。用户确认的是开始受控恢复，不能宣传为立即完成还原。

回滚开始后关闭继续合入的通道；一部分仓库已经撤回、另一部分仍待审时显示部分恢复。历史交付与恢复记录同时保留，不覆盖原先的实际结果。

## 故障分类与默认处理

| 情况 | 处理 |
| --- | --- |
| 通知失败，任务已登记 | 重发通知，不新建任务 |
| 执行前准备失败 | 保留阻塞原因，可重试准备 |
| 工作中断但原现场可用 | 恢复原尝试或受控新尝试 |
| 原成员无法工作 | 在同队内换人或升级人工 |
| 候选基准过期或发生冲突 | 创建修复任务，关闭合入门禁 |
| 验证不通过 | 针对失败原因返工，不降低判据 |
| 外部服务不可用 | 记录外部阻塞及下次检查，不假报业务成功 |
| 交付已部分完成 | 预览继续修复或整组回滚，保留每仓事实 |
| 临时环境清理失败 | 单独重试清理，不重复验证 |

## 验收

1. 同一故障反复被发现只形成一个当前恢复事项。
2. 多人并发决定只接受一份；证据更新后拒绝旧预览提交。
3. 自动恢复在预算耗尽后停止并产生可处理待办，不无限循环。
4. 换人后旧成员的成功回报不会覆盖新成员的状态。
5. 回滚预览完整展示所有仓库；已合入部分通过反向请求恢复，不抹除历史。
6. 回滚未全部核实完成时不显示整组已恢复。

# 11 · 能力与运营管理

## 范围

本册将已有技能、工具与运营规则转为完整产品要求。基础能力有现状依据，完整管理页面及真实服务联动按补齐范围交付，不应仅凭一张管理页面宣称已经可用。

## 技能与工具能力

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| CAP-01 | 能力目录 | 展示智能体可用的技能与外部工具、用途、适用角色、版本、可用性和授权范围 |
| CAP-02 | 技能版本登记 | 登记技能名称、版本、来源、说明和负责人，保留每个发布版本；同版本内容不可悄悄替换 |
| CAP-03 | 评估与结果 | 对技能版本执行正常及失败场景评估，记录通过或失败、评估人、时间及证据；无证据不能进入试用 |
| CAP-04 | 小范围试用与发布 | 指定试用工作区，通过试用后再扩大使用；试用失败退回不可使用状态，保留失败原因 |
| CAP-05 | 技能回退 | 撤回问题版本，后续任务不再选择；已经发生的使用保留历史，再次发布须用新版本 |
| CAP-06 | 能力组合快照 | 每次任务显示实际采用的技能版本组合，能追溯来源与适用范围，不随最新目录变化 |
| CAP-07 | 工具调用策略 | 配置超时、有限重试、适用任务、审计要求和降级行为；有副作用的动作不得无约束重试 |
| CAP-08 | 工具健康与降级 | 连续超时达到阈值后限制新的高风险动作，成功恢复后清除该原因的降级；展示当前状态和触发来源 |

技能生命周期为草稿、评估中、小范围试用、正式发布、已撤回。进入试用至少需要合格评估且没有失败证据；正式发布必须有试用阶段证据。试用失败不能只弹出提示后继续被选用。

## 运营功能

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| OPS-01 | 容量总览 | 查看排队工作、活跃执行、待处理交付与平台准备事项的当前量、上限、使用比例及更新时间 |
| OPS-02 | 容量保护 | 低于 80% 为可用，80% 至不足 100% 为承压，达到上限为饱和；状态未知单列，不能当成空闲 |
| OPS-03 | 接入限流 | 饱和时拒绝新工作并告知建议重试时间；承压时优先处理恢复及可安全重复的既有操作 |
| OPS-04 | 告警联动保护 | 可选择仅通知、限制新的外部修改、暂停新需求；不能藉此自动合入、回滚、删除业务资料或终止运行成员 |
| OPS-05 | 多告警恢复 | 只撤销当前恢复告警施加的保护，其他活动告警仍有效；展示保护来源及解除原因 |
| OPS-06 | 数据保留策略 | 分别配置用量、轨迹、日志、已恢复告警和通知证据的保留时间，展示清理量与结果；活动告警和业务审计证据不按普通日志清理 |
| OPS-07 | 统一定位 | 根据需求、任务、执行或追踪标识汇总关联事件和证据；无法证明的关联明确标为近似 |
| OPS-08 | 升级与恢复准备 | 展示当前版本兼容性、最近备份、恢复演练、协作资料备份和临时现场可恢复性；缺少真实依据显示待配置或外部阻塞 |

容量来源、真实通知渠道、备份和恢复演练应独立标明是否接入。管理页面只有策略、没有真实数据时，不能展示绿色“运行正常”。

## 运营角色与配置

管理员维护能力、容量和保留策略；审计人员按授权查看历史。配置变更记录操作者、时间、旧值、新值和理由。运行中的任务继续保留所用版本，涉及权限与安全撤销时应明确影响及处理方式。

## 验收

1. 没有合格评估证据的技能不能进入试用或发布，失败证据会阻止晋级。
2. 已撤回版本不再进入新任务，但历史任务仍能显示当时采用版本。
3. 工具超时按有限规则重试，状态与审计中能查到结果。
4. 容量来源不可用时显示未知；饱和时新增需求收到可操作的等待提示。
5. 两条告警同时触发保护，恢复其中一条不会错误解除另一条。
6. 普通保留清理不删除活动告警、交付验证和人工决策。
7. 没有实际备份或恢复演练证据时，升级准备不能显示全部通过。

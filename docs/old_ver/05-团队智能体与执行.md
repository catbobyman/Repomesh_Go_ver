# 05 · 团队、智能体与执行

## 团队与智能体

| 编号 | 功能 | 规则与呈现 |
| --- | --- | --- |
| AGT-01 | 仓库常设团队 | 为仓库配置一个队长和至少一个执行成员；后续需求使用既有团队，避免重复建团；成员池支持 1 至 20 名执行成员 |
| AGT-02 | 团队总览 | 展示所属仓库、关联需求、队长、成员、工作方式、任务概况和状态；可进入需求及房间 |
| AGT-03 | 智能体花名册 | 展示角色、业务启用状态、仓库归属、所属团队、当前任务和实际运行状态；未知运行状态单独标识 |
| AGT-04 | 层级协作 | 组织负责人对接仓库队长，队长对接本仓成员；问题与结果逐级汇总，不允许以聊天绕过责任链 |
| AGT-05 | 双房间 | 每队有团队房和负责人沟通房，显示成员、最近消息、时间及活动状态；空房间如实为空 |
| AGT-06 | 房间阅读与工作视图 | 切换消息流和本仓计划、任务图、规格；查看任务通知、回报、追问、答复、进度、决策及上下文摘要 |

AGT-01 至 AGT-06 为保留功能。手动在房间发起业务变更和澄清的统一输入入口为补齐项；自由聊天不能自动成为正式指令。

## 两种工作方式

| 编号 | 功能 | 用户价值与限制 |
| --- | --- | --- |
| RUN-01 | 托管原生执行 | 成员在平台托管环境中完成任务，队长初审后由独立验证能力复核；用户无需启动本机执行工具 |
| RUN-02 | 本地智能体执行 | 使用操作者本机已登录的智能体工具完成工作；保持相同的范围、任务、验证与交付规则 |
| RUN-03 | 开工前就绪检查 | 按本轮实际选中的工作方式检查所需成员和验证能力；显示就绪、未连接、检查中、降级、过期、失败及原因 |
| RUN-04 | 本地启动与停止 | 管理员查看本机启动器，启动并检查已登记成员、停止受管理成员、刷新状态；启动器不可达时保留人工启动指引 |
| RUN-05 | 逐成员状态 | 并列显示本机运行状态与任务就绪状态、角色、最后报告时间、失败阶段；“进程存在”不能当成“能够接活” |
| RUN-06 | 工作方式受控切换 | 组织可设默认方式，仓库团队可覆盖；存在活跃工作时先处理在途任务，再确认新方式就绪；保留身份与历史 |

RUN-01 至 RUN-05 为保留范围，但不同环境就绪性必须实际验证。RUN-06 为补齐：当前选择能力与完整安全切换流程不能混为一谈。本地一键启动的现有适用宿主是 Windows，其他宿主为扩展。

## 任务执行

| 编号 | 功能 | 规则与结果 |
| --- | --- | --- |
| TSK-01 | 任务分配与领取 | 组织负责人分配仓库工作，仓库队长或平台规划确定成员任务；成员只能领取自己的任务 |
| TSK-02 | 批次与并行 | 依赖满足且有可用成员时开始；同一成员同一时刻只能执行一个活跃任务，不同仓库可并行 |
| TSK-03 | 执行尝试记录 | 显示派发、通知、领取、开始、候选提交、初审、复验和结束；分别记录时间与当前尝试 |
| TSK-04 | 候选结果提交 | 成员提交变更清单、自测证据及未完成事项；结果不完整、越界或基准不匹配时拒收并说明 |
| TSK-05 | 队长结果初审 | 队长给出接受、要求修改或阻塞及理由；接受只放行独立复验，要求修改产生新尝试 |
| TSK-06 | 重派与任务范围 | 有权限的用户预览当前轮或选定任务的重派范围，确认后记录新尝试与原因，保留旧结果 |
| TSK-07 | 中断与补充输入 | 明确展示等待输入、外部条件缺失或会话中断；具备条件时恢复，不以假完成结束任务 |

以上为保留范围。自动恢复、换人和无健康成员的处理见第 08 册。

## 房间与环境侧栏

房间右侧展示当前仓库执行、变更摘要、所属交付组、门禁、环境状态和事件时间线。跨仓总览留在需求详情，不把其他仓库的执行状态混入当前房间。活动标识表示有正在处理的任务，不代表某个成员一定在线。

## 隔离与权限

执行只在获准仓库与工作范围内进行。不同需求的材料和尝试相互隔离；重试不能扩大权限。接入新的智能体工具时，显示支持情况、认证状态和已验证能力，不能因为出现在工具列表里就承诺全部可运行。

## 验收

1. 同一仓库参与两个需求时沿用常设团队，各需求的任务与材料不混淆。
2. 任一必需成员或验证能力不就绪，开工保持阻塞并指出对象。
3. 同时派给同一成员的任务只允许一个执行，其他任务可解释地等待。
4. 候选初审接受后仍显示待复验；成员自行宣称成功不能推进到交付完成。
5. 旧尝试的迟到结果保留记录，但不能覆盖新尝试。
6. 房间断开或无消息不直接把正式任务判定为失败。

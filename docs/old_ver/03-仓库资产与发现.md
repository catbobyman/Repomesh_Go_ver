# 03 · 仓库资产与发现

## 目标

用户无需提前知道全部受影响仓库，也能获得有依据的范围建议，并控制最终参与交付的资产。

## 仓库资产功能

| 编号 | 功能 | 规则与呈现 |
| --- | --- | --- |
| REP-01 | 仓库与组织接入 | 在仓库页输入单仓或组织地址，识别受支持的托管平台与地址类型，确认后开始扫描；未知或不可达地址给出说明 |
| REP-02 | 批量扫描进度 | 展示扫描总量、已登记、已存在跳过、失败数与完成状态；支持离开页面后继续查看 |
| REP-03 | 整体重新扫描 | 以整批重扫作为恢复动作，已登记仓库不重复创建；保留前次扫描结果与证据 |
| REP-04 | 仓库列表与画像 | 展示名称、所属工作区、主要职责、能力摘要、扫描时间、画像版本、团队情况及关联需求；画像无法获得时明确标注 |
| REP-05 | 依赖关系与发现证据 | 展示仓库之间的已识别关系、证据来源、可信程度和更新时间；建议关系与已证实关系可区分 |
| REP-06 | 团队与能力档案 | 从仓库进入团队接入，选择工作方式；配置该仓是否提供跨仓联调能力，并说明只影响后续新编制 |
| REP-07 | 仓库验证配置 | 配置本仓必跑检查及允许修改的测试范围；校验不完整时不给出“可验证”的误导状态 |

REP-01 至 REP-07 为保留功能。扫描失败明细的完整自助排查视图为补齐项，界面只能展示适合用户查看的原因，不暴露敏感连接信息。

## 需求发现功能

| 编号 | 功能 | 规则与呈现 |
| --- | --- | --- |
| DSC-01 | 需求分析 | 提炼目标、业务行为、约束、缺失信息和待澄清问题；指明输入版本与分析状态 |
| DSC-02 | 候选仓库评分 | 在允许使用的仓库集合中给出相关候选、评分、理由、匹配能力和依赖证据；评分不等于授权 |
| DSC-03 | 三档范围分类 | 每仓给出“必改／待定／不做”建议，并允许获准人调整；保留建议值、最终值和调整意见 |
| DSC-04 | 依赖复核提醒 | 排除项若与保留仓存在已确认依赖，显示复核提示；未解析清楚的关系保留为问题，不能静默丢弃 |
| DSC-05 | 范围确认 | 汇总三档清单、风险、缺失权限及确认人；确认绑定当前版本，后续变更保留新的确认记录 |
| DSC-06 | 分析失败恢复 | 保留已取得的候选与证据，显示失败步骤；允许重试，不能显示虚假评分或完成进度 |

以上为保留功能；仓库画像的更细粒度人工管理界面属于补齐项。

## 发现流程

需求详情固定显示四步：需求分析、候选评分、分档审批、生成计划。用户可看到哪些步骤已完成、正在处理、待处理或失败。只有有效范围确认后才可以形成可执行计划。

“待定”仓库可以继续参与讨论，不自动获得执行资格。计划应明确最终包含哪些仓库；若计划生成过程中需要改变已确认范围，必须回到范围确认。

## 输入与限制

- 仓库接入要求明确工作区和受支持地址；私有资源的访问授权由管理员管理，不在普通扫描表单索要个人凭证。
- 同一仓库重复接入不会产生两份长期资产记录。
- 范围建议可提示“缺少必要权限”，不能为了让计划可执行而隐藏必需仓库。
- 产品只在当前授权资产集合内发现，任意互联网仓库搜索不属于现有发现能力。
- 候选理由应完整可展开，不能只保留分数而丢掉用户判断依据。
- 原始分析依据与人工最终决策同时留存；新扫描不改写历史决策使用的画像版本。

## 页面状态

无仓库时显示添加入口；正在扫描时显示实际计数；部分失败显示已完成部分及整体重扫；扫描服务不可用与仓库不可访问分别提示。发现页面区分尚未开始、分析中、需要澄清、待确认、生成完成和失败。

## 验收

1. 输入组织地址后出现多仓扫描进度，重复扫描不产生重复仓库。
2. 每个候选能展开理由与证据；未取得证据时不展示编造的结论。
3. 将“待定”改为“必改”并提交意见后，计划范围和历史决策能反映调整。
4. 排除一个有必需依赖的仓库时，用户能看到复核提醒。
5. 必需仓缺少权限或存在未解决范围问题时，开工不可用，并说明处理路径。
